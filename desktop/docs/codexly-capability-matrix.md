## 引擎

两种引擎均支持 ACP 任务执行、历史恢复、审批、中断、排队、配置选项、提交说明、搜索与显式配置的定时任务。认证、权限与模型选项来自官方 adapter 返回的能力。当前生产入口不公布旧执行器的 Goal、Review、分叉、专用压缩、运行中引导、Skills / MCP / 插件管理及反馈上传能力。完整边界见[智能体配置](../../docs/agent-engines.md)。

已有任务绑定引擎，不因修改新任务默认值而改变。搜索通过共享 ACP 历史匹配可见正文，返回精确回合锚点；冷历史仅加载原会话，不重发问题。

## 执行与存储边界

Web 浏览器通过 HTTP / WebSocket 访问本地服务，再由各引擎适配器执行。桌面通过 Tauri invoke / Channel 进入原生层，两种引擎均由同一个共享 ACP stdio 宿主执行。桌面执行不依赖另行启动的 Web 服务。

同机同一系统用户的桌面与 Web 共用 `~/.codexly` 项目、任务、历史和常用提示词；移动浏览器访问 Web 主机。应用默认配置保存在 ACP 设置目录，原厂认证、策略及会话仍由官方 adapter 管理。共享存储不提供跨电脑云同步，也不表示两个独立进程可以同时控制同一运行会话。

运行时随桌面包分发、按需启动，缺失或损坏时修复安装；不再按旧文档在首次启动下载。Web 继续使用 npm 依赖。项目相关上下文会发给配置的模型服务，“本地”不代表离线推理。
