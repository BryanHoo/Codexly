Codexly 将 AI 编程任务、对话、审批、项目文件和 Git 操作集中在一个桌面工作台中，适合持续处理真实项目，而不必在多个工具之间切换。

## 主要功能

- 运行项目任务或临时任务，实时查看回复、命令、计划、审批和文件变更
- 在独立透明小窗中持续查看任务输出，不占用主工作台空间
- 使用持久化任务队列安排后续工作，并在执行前撤回修改、排序或取消消息
- 添加文件、图片与音频，在纯文本输入框中使用 `@` 引用项目文件、`$` 引用 Skills，并在任务队列中可靠恢复附件
- 在扩展中心安装和管理 Skills、官方插件与第三方市场，并管理 MCP 服务和运行时热重载；刷新官方插件可同步状态，并提示部分失败
- 在固定问答区处理异步问题，通过跨客户端任务锁避免并发交互冲突，并在续聊时恢复线程模型与思考量
- 最多同时打开四个任务分屏，各自保留草稿与消息队列，项目文件、Git 面板和终端跟随当前聚焦任务
- 拖动分割线调整分屏宽高，从任务标题栏新建任务；收起输入框后仍显示当前模型与思考量
- 在项目文件源码预览中直接编辑文本，支持撤销重做、手动保存和失焦自动保存
- 流式查看推理摘要和操作分组，在上下文与时间线中查看运行时警告及工具实时耗时
- 阅读增量渲染的 Markdown 回复，缩放、拖动消息图片、项目图片与壁纸，并切换适应窗口或原始尺寸
- 直接预览聊天附件、文件链接与项目文件树中的 PDF，通过单文件授权读取本机文档
- 查看 Markdown 回复中嵌入的任务本地图片，并复用图片缩放预览
- 使用项目级原生集成终端运行命令，并在多个持久会话之间切换
- 使用全局快捷键快速创建任务、切换区域和执行常用工作台操作
- 使用可视化重复规则创建定时任务，按工作日、周末、星期或月份配置计划，并预览后续执行时间
- 在「设置 → 智能体配置 → 历史文件存储」请求后台压缩超过 7 天未写入的历史；共用历史目录的其他 Codex 客户端需支持压缩格式
- 自动安装并校验应用私有 Codex `0.162.0` 运行时，无需配置全局 Codex
- 为每个任务选择模型、思考量、快速模式、审批方式和文件访问范围
- 为自定义 Provider 在线发现模型，并在不可用时回退本地模型目录
- 新建项目及目录，管理多个项目根目录、临时任务和归档任务，自动生成新任务标题，并从现有对话分叉新任务
- 通过侧栏任务的项目标签识别跨项目任务的来源；项目收起时仍显示未读完成、等待审批或运行状态
- 跨项目搜索任务、历史消息和项目文件，并精确定位历史命中位置
- 浏览和管理项目文件，在检查器文档标签中切换文件预览与 Diff，审查未提交变更与提交历史，并复制保留原始格式的 Markdown 消息
- 创建或切换 Git 分支和 worktree，直接在原项目中创建 worktree 任务，选择文件后提交或推送变更；Git 操作仅作用于项目根目录对应的仓库，普通子目录不会借用父仓库
- 支持简体中文与 English、系统通知、最小化到托盘和工作台宠物

## 快速开始

1. 从 [Releases](https://github.com/BryanHoo/Codexly/releases) 下载发布包，按[安装指南](./docs/installation.md)安装。
2. 启动 Codexly，等待应用自动安装并校验私有 Codex 运行时。
3. 添加项目或创建临时任务，开始使用。

支持 Windows、Ubuntu 和 macOS；架构、最低系统版本及 Modern / Legacy 选择见安装指南。

## 使用方式

处理仓库时，先添加一个或多个本机目录作为项目根，再创建任务并提交需求。无需项目上下文时，可直接创建临时任务。消息可以附加文件或图片，也可以引用项目文件和 Skills。

从侧栏任务菜单打开任务分屏，或在聊天空白处右键选择向上、向下、向左或向右分屏；最多四个分屏。macOS 使用 `⌘+⌥+方向键`，Windows / Ubuntu 使用 `Ctrl+Alt+方向键`。点击分屏后，项目文件、Git 面板与终端会跟随当前任务。

任务运行期间，可以立即发送补充要求，也可以将后续消息加入队列。任务控件用于设置模型、思考量、快速模式、审批方式和文件访问范围。

拖动分割线可调整相邻分屏的宽高。从通知、搜索或定时任务跳转时保留分屏布局，并聚焦目标任务。

打开项目文本文件的源码预览即可编辑，Markdown 需切换到源码模式。编辑区失焦、离开文件或切换窗口时自动保存，也可按 `⌘/Ctrl+S` 手动保存。支持最大 2 MiB 的 UTF-8 文本，保留换行与 BOM；更大或不支持的文件保持只读。保存失败或外部修改冲突时，当前窗口保留草稿并显示恢复操作；关闭面板或退出应用前会保护未保存编辑。草稿仅保存在内存中，强制退出或崩溃后不保证恢复。

工作台提供项目文件、代码变更、Git 历史、分支、worktree、审查、提交和推送操作。归档任务可恢复，也可在确认后永久删除。
