# Web 前端质量规范

## 测试

- 流式 Markdown 预处理必须覆盖普通 `]`、已闭合文件链接、跨 Chunk 的 `](` 和未闭合长链接；只扫描新增内容，链接闭合时再规范化目标。用累计扫描量验证线性开销，不能仅用整段耗时阈值代替；Chromium/WebKit 交互回归须在持续输出时点击外部按钮、编辑输入框并停止输出。

- Native WebView 的真实 Codex 冷启动包含受控下载，必须在 WDIO 配置中预先设置外层超时；hook 内修改 `this.timeout` 无法延长 WDIO 已启动的计时器。普通交互测试仍保持较短超时，不能统一放宽。
- Chromium/WebKit 浏览器测试默认最多并发 2 个 worker，避免桌面与 WSL 有限资源下的渲染争用；布局或动画断言偶发失败时先复现并检查渲染状态，不得直接放宽断言阈值。
- 异步界面测试须等待实际 DOM 或可见布局就绪，不能把请求已经发出、虚拟容器暂时置底或固定毫秒延时视作渲染完成；提交回弹采样必须在末条历史消息可见且列表置底后开始。
- 虚拟行的 ResizeObserver 测量若延迟到下一帧消费，必须避免旧 entry 覆盖 React 提交阶段同步的新高度。回归须保留真实旧测量，在新布局提交后交付，再逐帧检查尾部留白与置底，且保持历史 DOM 有界。
- 原生终端延迟批次包含 200 次采样和帧调度，必须单独设置有界的 WebDriver 脚本超时并在结束后恢复；批次超时与单次交互性能目标分别验证，不能将采样成功等同于性能达标。
- Query、事件排序、状态转换与 mock 传输使用 `src/**/*.test.ts` 下的 Vitest 单元测试
- 用户可见交互变更检查键盘操作、可访问名称及禁用状态
- 工作台布局至少验证 `1280×720` 与宽屏桌面视口，无页面级横向溢出
- 对话虚拟化必须在 Chromium 与 WebKit 双引擎验证至少 207 个动态高度 Turn、约 11,505 个 Timeline Item，覆盖有界 DOM、冷跳无空白、prepend 锚点、流式增长置底和用户向上阅读
- 已有历史中再次发送消息必须逐帧验证追加期间无反向回弹，并检查待处理尾部保持挂载；不能仅断言最终置底，以免漏掉估算高度、末行留白或悬浮控件显隐造成的中间跳动。真实 Composer 回归必须覆盖 `turn.started`、用户 Item 与提交响应的不同到达顺序，确保满屏聊天始终只显示一份运行态，不因响应返回移除重复占位而回弹。
- 发送过程还须在本帧布局完成后检查新消息与运行提示无重叠；已知输入须与时间、运行态处于同一测量行，首次可见位置在回复增长前须保持稳定。结构更新的行高、容器高度和置底须在绘制前同步，不能仅测量新挂载行或等待下一帧补滚动。延迟到达的空 `turn.started` 不得清空已显示的提交消息，权威用户 Item 到达后仍须原子接管，且只显示一份用户输入。
- 提交气泡首次显示后须持续保留同一 DOM 节点并保持可见；权威 ID 接管不得重挂首条用户消息，也不得把它追加到已到达的回复后面。浏览器回归须包含多回合长历史和回复先于权威用户 Item 到达的顺序。
- 协议变更同时验证 `src/protocol/` Schema 与 `src/client/` 消费端

## 验证

- 运行 `pnpm check:web`
- 仅前端变更运行 `pnpm check:web`；涉及 Rust/Tauri 时额外运行 `pnpm check:rust`
- 跨前后端变更或合并前完整验证运行 `pnpm check`
