# 前端组件规范

## 规则

- 功能组件放入对应 `features/<feature>/components`，跨功能基础组件复用 `shared/components/core`。
- 优先组合现有 Radix UI 基础组件，并使用 `lucide-react` 图标；保持键盘操作、焦点和可访问名称完整。
- 通过明确的 props 或现有 Context 传递依赖，避免组件直接创建网络客户端或全局单例。
- 新 Task 首轮启动成功后，使用 `turn/start` 返回的 checkpoint 和乐观 Snapshot 预热标准任务缓存，再导航并从该 checkpoint 接管实时事件；首屏不得额外请求尚未稳定的任务历史，也不得用重试掩盖交接竞态。
- 临时任务没有 Project 根目录，中栏顶部不得显示目录快捷打开入口。
- 临时任务分组在新建按钮左侧提供 hover 与键盘聚焦可见的已归档入口，并复用 Project 已归档弹窗的搜索、恢复、永久删除和分页逻辑。
- 复杂组件拆分渲染、状态和数据转换职责，单个代码文件保持在 500 行以内。
- 工作台宠物 Overlay 关闭时不得主动请求目录或资产；开启后再按选中项加载 Canvas 渲染模块和图片。
- 工作台背景图片加载后，Dialog、Sheet、Tooltip、菜单、通知与宠物气泡统一使用 95% 不透明的浮层表面；未使用核心 Portal 组件的手工浮层添加 `data-floating-surface` 接入同一规则。
- 工作台背景使用独立设置菜单；自定义模式以方形缩略图展示浏览器本地图片集合，支持重复上传、删除和切换当前背景，图片 Blob 存入 `IndexedDB`，偏好仅保存选中图片 ID 与显示参数。
- 工作台背景图片加载后，根据图片代表亮度显式切换前景与遮罩 Token，并同步切换 `color-scheme`，使文字、图标、控件和分隔线保持同一明暗语义；取色不可用时保留用户主题配色。
- 工作台背景使用按 `CSS size × DPR` 分配 backing store 的 Canvas；仅在图片来源、视口尺寸、DPR 或模糊值变化时重新解码预处理，连续 resize 必须合并执行，正常合成阶段不得使用 CSS `filter` 模糊。
- Inspector 顶部标签栏使用固定且不可伸缩的工作台 Header 高度，文件预览等滚动内容仅填充剩余高度；避免 `auto` Grid 行与 `height: 100%` 子项循环参与尺寸计算，确保 Windows 经典滚动条环境不拉伸顶部栏。
- Inspector MCP 区域只显示当前任务服务的名称、连接状态和工具数量，不展开工具名、认证、版本或启动错误详情。
- 用户打开全局设置中的宠物目录后，应在后台准备所有缺失的预览资源，所有已就绪目录项无论是否选中都直接显示预览；下载不得禁用目录选择或阻塞全局设置保存。
- 工作台宠物位置使用工作区归一化坐标持久化，并支持安全区约束、键盘移动和减少动态效果偏好。
- 每个活动 Task（包括临时任务）使用独立宠物气泡并以 `AgentTask.title` 为标签；无项目根的临时任务不显示路径 Tooltip；默认逐层叠放且后续层只露出底部三分之一，悬停或聚焦宠物区域时展开；后台 Task 完成后将 loading 状态替换为完成状态并持续保留，折叠时完成气泡排在首位且处于最高层，直到用户点击气泡或自行进入对应 Task；点击气泡通过应用内路由进入对应 Task；宽度随内容伸缩，最大为 `12rem` 且不得超出视口。
