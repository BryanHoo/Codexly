# 前端组件规范

## 规则

- 功能组件放入对应 `features/<feature>/components`，跨功能基础组件复用 `shared/components/core`。
- 定时任务编辑器通过 Composer 捕获模式复用提示词、附件、Skill 与 Turn 设置语义，捕获提交不得创建即时 Task。
- 定时任务执行同步挂载于全局 Provider，通过单条 WebSocket 接收落库变更通知，不周期性轮询完整任务列表；首次连接及断线重连重新校准，连续通知合并，请求期间的新通知必须补读。运行记录补齐实际 Task ID 时仅刷新所属项目的普通、固定与搜索列表。历史记录跳转必须重新读取快照并检查普通及固定归档列表（含分页），已删除或归档时留在原页提示，网络错误不得误报为任务已删除。
- 定时任务调度字段必须随重复类型联动：仅一次和自定义规则配置日期时间；每天和工作日配置时间；每周配置周几和时间；每月配置每月几号和时间。已有预设 RRULE 必须从规则本身回填这些字段，不得从生效日期反推。
- 优先组合现有 Radix UI 基础组件，并使用 `lucide-react` 图标；保持键盘操作、焦点和可访问名称完整。
- 工作台左栏功能入口固定按“新建任务、定时任务、任务看板、扩展中心”排列；扩展中心页签切换必须更新路由，不以仅存在于组件内的状态替代 URL。
- 通过明确的 props 或现有 Context 传递依赖，避免组件直接创建网络客户端或全局单例。
- 工作台附件菜单在本机模式仅提供“当前设备”且不显示单一来源标题，在 LAN 模式同时提供“当前设备”和“部署主机”并显示两个来源标题；所有附件动作左对齐，每类均支持图片和普通文件。当前设备使用浏览器原生文件选择并经 multipart 上传，部署主机使用 Host 文件选择器导入，保留绝对路径和文件系统根浏览且不按项目根目录限制。
- 排队及编辑回撤中的附件尚未进入历史消息，预览必须使用 Project 临时附件地址；发送后时间线再使用 Task 历史附件地址。
- 新 Task 首轮启动成功后，使用 `turn/start` 返回的 checkpoint 和乐观 Snapshot 预热标准任务缓存，再导航并从该 checkpoint 接管实时事件；首屏不得额外请求尚未稳定的任务历史，也不得用重试掩盖交接竞态。
- 临时任务没有 Project 根目录，中栏顶部不得显示目录快捷打开入口。
- 临时任务分组在新建按钮左侧提供 hover 与键盘聚焦可见的已归档入口，并复用 Project 已归档弹窗的搜索、恢复、永久删除和分页逻辑。
- 复杂组件拆分渲染、状态和数据转换职责，单个代码文件保持在 500 行以内。
- 异步问题与引导消息共用 Composer 内部宽度容器，显示在输入框上方且与输入框等宽，内部有界滚动；允许不回答直接关闭当前问题，关闭标识按 Project、Task 和问题记录在浏览器本地持久化，重开任务或刷新页面不得再次显示已关闭问题。关闭不提交回答且不影响后续新问题展示，关闭记录不得随正文草稿或待办编辑作用域变化。历史仅展示只读问题；预选项必须显式发送，所有问题允许自由输入，失败保留草稿，发送不清空正文草稿或进入跟进队列。
- 续聊模型与思考强度从 `threadConfiguration` 独立回填；用户手动选择优先，模型目录继续校验可用性。问答区只订阅完整 Item 结构变化，不拼接流式正文。
- 运行中时间线的连续 `command` 与 `tool`（包括映射为 `tool` 的 MCP 调用）在后续 Assistant 文本出现后统一折叠；空白 `reasoning.summary` 必须在创建 Item 组件前过滤且不得截断连续操作分组，有内容的摘要继续作为可见分组边界。
- 工作台宠物 Overlay 关闭时不得主动请求目录或资产；开启后再按选中项加载 Canvas 渲染模块和图片。
- 工作台背景图片加载后，Dialog、Sheet、Tooltip、菜单、通知与宠物气泡统一使用 95% 不透明的浮层表面；未使用核心 Portal 组件的手工浮层添加 `data-floating-surface` 接入同一规则。
- 全局设置使用独立页面与分组搜索导航，保留后台工作台状态；分区按需加载，常规偏好立即应用，服务端设置串行自动保存并合并文本输入。保存失败保留草稿，返回前等待最新快照落盘。
- 自动保存状态按字段隔离，不得因修改单项禁用或重载同组的其他控件。提交期间保留当前选择，失败仅回退当前项；共享配置的写入串行执行，完整对象请求必须在出队时合并最新缓存，避免旧响应或旧快照覆盖其他字段。保存与错误提示不得挤动设置内容布局。
- 工作台背景归入常规设置，以摘要预览和独立图库选择图片；自定义图片 Blob 存入 `IndexedDB`，支持上传、删除、预览与选择；Bing 支持近期目录、固定日期与每日更新。设置页面共用工作台背景和前景配色，选择图片及调整模糊、遮罩时实时显示；弹窗与保存提示继续使用浮层材质以保持可读性。
- 工作台背景图片加载后，根据图片代表亮度显式切换前景与遮罩 Token，并同步切换 `color-scheme`，使文字、图标、控件和分隔线保持同一明暗语义；取色不可用时保留用户主题配色。
- 工作台背景使用按 `CSS size × DPR` 分配 backing store 的 Canvas；仅在图片来源、视口尺寸、DPR 或模糊值变化时重新解码预处理，连续 resize 必须合并执行，正常合成阶段不得使用 CSS `filter` 模糊。
- Inspector 顶部标签栏使用固定且不可伸缩的工作台 Header 高度，文件预览等滚动内容仅填充剩余高度；避免 `auto` Grid 行与 `height: 100%` 子项循环参与尺寸计算，确保 Windows 经典滚动条环境不拉伸顶部栏。
- Inspector MCP 区域只显示当前任务服务的名称、连接状态和工具数量，不展开工具名、认证、版本或启动错误详情。
- Inspector 中处于 `blocked` 状态的 Goal 必须同时提供恢复与清除操作；恢复应将目标切回 `active`，不得把可恢复状态展示为无操作终态。
- 用户打开全局设置中的宠物目录后，应在后台准备所有缺失的预览资源，所有已就绪目录项无论是否选中都直接显示预览；下载不得禁用目录选择或阻塞全局设置保存。
- 工作台宠物位置使用工作区归一化坐标持久化，并支持安全区约束、键盘移动和减少动态效果偏好。
- 每个活动 Task（包括临时任务）使用独立宠物气泡并以 `AgentTask.title` 为标签；无项目根的临时任务不显示路径 Tooltip；默认逐层叠放且后续层只露出底部三分之一，悬停或聚焦宠物区域时展开；后台 Task 完成后将 loading 状态替换为完成状态并持续保留，折叠时完成气泡排在首位且处于最高层，直到用户点击气泡或自行进入对应 Task；点击气泡通过应用内路由进入对应 Task；宽度随内容伸缩，最大为 `12rem` 且不得超出视口。
