# React 组件规范

## Purpose

约束 `apps/web` 内组件的职责、可访问性和渲染边界。

## Rules

- 用户主动操作需要额外确认的成功结果与所有失败结果统一通过应用根级 Sonner toast 展示，Feature 组件不得渲染动作结果成功文案或错误块，也不得直接导入 Sonner；失败后仍应保留可重试的输入、草稿和必要业务状态。打开外部应用、生成并直接回填内容等已有明确可见反馈的动作成功时必须静默，失败时仍通过根级 toast 展示原始错误。查询加载错误、表单输入校验、Timeline/Tool 领域错误和待审批状态不属于动作结果，继续在所属视图表达。Codex 与 Git 动作失败的 toast 必须原样显示 Client 收到的底层错误文本。
- `PairingGate` 必须位于 Router 和全部业务 Provider 之外；LAN 未认证时只显示品牌、访问密码表单、提交、通用错误与重试状态，不挂载 Project、Settings、Composer 或 Event Runtime，也不创建独立登录路由。
- 访问密码表单必须提供可访问 Label、提交状态和键盘焦点；密码只保留在表单局部状态。LAN 设置页必须提供明确注销动作，并复用顶层 Access 清理边界。
- 每个组件只承担一个可描述的界面职责，紧凑工作台界面避免装饰性嵌套卡片。
- 会触发网络 Mutation、宿主应用或持久化副作用的按钮和表单必须在事件入口同步单飞，直到当前 Promise 成功或失败后再允许执行；不得只依赖下一次 React 渲染的 `isPending`，也不得使用固定毫秒 debounce。锁按 Project、Task 或请求身份隔离，切换作用域不能被旧请求阻塞；失败重试继续遵循原 `Idempotency-Key` 规则。
- 左栏添加 Project 的前台完成边界只到注册响应；成功后必须立即用响应更新项目缓存并关闭目录选择器，不得等待或广域失效 Task、Snapshot、Git 等无关查询，也不得改变当前 Project/Task 路由。手动输入完整绝对目录时，只有当前目录查询成功并返回规范化路径后才允许直接添加，且该方式只能提交单个 Project 根；多根 Project 必须通过目录树 checkbox 选择，不能与直接输入目标混合，继续编辑路径或切换父目录、文件系统根时必须立即使直接目标失效。新 Project 的 Task 数据仅在侧栏展开等真实消费发生后按需读取。
- Inspector 页签固定按“上下文、项目、变更、历史”排序，并只允许用户主动切换；“项目”始终显示，持久化 `taskId` 存在后显示“上下文”，Git Project 存在未提交变更时显示“变更”，Git Project 显示“历史”。Project 草稿首次进入时默认选择“项目”，持久化 Task 首次进入时默认选择“上下文”，当前标签失效时只在渲染时回落到“项目”；后台终端、子代理、计划和 Task 运行态不得自动改变当前页签，Git 提交入口仍直接选择“变更”。Inspector 关闭时必须停用全部标签专属 Query、轮询与副作用；打开后只挂载和激活当前有效标签，失效标签回落后的数据门控必须同步跟随“项目”，不得继续执行原标签逻辑；“变更”和“历史”的模块仅在用户首次选择对应标签时异步加载。上下文仅在 Git Project 存在未提交文件时显示紧凑的“未提交变更”区块，区块只提供文件总数、汇总 `+/-` 和提交入口；统计内容不得使用独立卡片背景、边框或分隔线，只用与其他上下文模块一致的单行紧凑排版组织。区块不得显示目录树、文件名、路径、逐文件统计或文件 Diff；Project 标签不得重复显示旧变更摘要，完整变更树只由“变更”标签承载，非 Git Project 或干净工作区不得显示整个区块。Project Inspector 顶部不得保留独立“运行环境”标题栏，首行直接展示 `24px` 高、带 `14px` 语义图标的紧凑标签且下方不显示分隔线；选中标签必须直接复用未选中标签的 hover 背景与文字颜色，未选中标签保持透明。桌面右栏默认宽度和拖拽最小宽度统一为 `320px`；拖拽最大宽度必须基于实际工作台宽度动态计算，使右栏最多占左栏之外剩余空间的一半。Inspector Project 文件树必须使用 Headless Tree 管理树语义、选择、展开和键盘状态，只加载项目根及已展开目录，并通过可见行虚拟化限制 DOM；Shell 不得按展开目录建立并行 Query 编排。Git Project 的变更文件或其最深可见祖先目录必须在行尾展示 `+/-`，目录展开后统计继续下沉到更深的可见节点；非 Git Project 不得请求详细 Git Diff 或执行文件树变更统计。文件树及其文件搜索必须统一排除 Finder 生成的 `.DS_Store` 元数据。文件树必须以默认展开的项目根文件夹名称开头，不在树外重复显示“项目文件”标题；Headless Tree 的隐藏根与可见项目根必须使用不同内部 ID，根节点展开状态只属于界面，不得作为相对目录路径发起文件查询。项目根节点 hover 或键盘聚焦时必须显示带 Tooltip 的刷新图标，单次操作重新读取当前根目录、全部已展开目录和 Project Git 状态，允许重新识别 Git 与非 Git Project，刷新期间保持可见并同步单飞。文件与目录节点 hover 或键盘聚焦时必须在行尾显示 `Ellipsis` 操作按钮，点击后打开与右键一致的菜单，菜单打开期间保持按钮可见；右键目标立即进入文件树选中高亮态。文件菜单顶层依次提供“复制名称”“复制相对路径”“复制绝对路径”“打开”“引用”，目录菜单只提供前四项；相对路径以 Project 根目录为基准，根节点使用 `.`，绝对路径必须把 Project 根目录与文件树相对路径组合为宿主绝对路径。只有“打开”使用二级菜单并复用同一宿主应用目录，文件菜单额外提供系统默认应用。项目根节点打开请求必须省略相对 `path`，由 Server 解析为项目根目录；项目根节点和所有目录均不得生成引用入口。“引用”必须把普通文件作为现有 `@path` Token 添加到当前 Project/Task Composer 草稿并聚焦输入框。菜单中的打开命令不修改中栏保存的默认应用。菜单必须脱离滚动容器裁剪并限制在视口内，打开后聚焦首项，支持级联键盘导航、Escape 和外部点击关闭，请求期间禁用重复操作。
- 上述固定标签顺序只约束常驻业务标签；存在当前可预览文件时必须在末尾追加“文件”标签，选择被关闭后立即移除，不得保留空标签。
- 中栏顶部右侧在桌面端必须常驻项目快捷打开组合控件，移动端隐藏整个模块：主按钮使用全局 `defaultOpenAppId`，默认项不可用时回退到首个可打开目录的宿主应用；菜单选择其他应用时直接打开当前项目根目录，且不修改全局默认值。项目根目录请求必须省略 `path`，目录入口不得提供 `system-default`；能力检测或打开请求期间禁用不可执行操作。桌面组合按钮可见高度固定为 `24px`，主按钮图标为 `14px`，下拉应用图标与文件树菜单统一为 `16px`。
- Inspector 的 MCP 区域必须用图标和文本共同展示 `starting | ready | failed | cancelled`；成功项展示工具数量、认证状态和版本，失败项展示失败原因并允许展开脱敏错误日志，不得渲染 Provider `serverInfo.description` 作为额外底部文案。清单 Query 读取失败时必须直接展示 Codex 原始错误消息、统一错误码和 HTTP 状态，不得只显示 `502`；手动重试失败只通过根级 toast 展示同一原始消息，不得在栏目内叠加动作错误。手动重试使用带 Tooltip 的图标按钮，提交或刷新期间禁用且显示进行中状态。
- Git 历史只从 Inspector 的“历史”标签进入，中栏 Composer 底部不得重复提供历史按钮；历史 Query 仅在该标签内容挂载后读取。历史内容必须展示活动仓库 Tab 自身的当前分支，无分支时显示 `detached HEAD`，未加载时显示明确读取状态且不得沿用上一仓库分支。根仓库直接展示提交列表，聚合模式使用可键盘导航的横向 Tab 分开展示直属子仓库，并在单次挂载期间按仓库独立缓存分页结果、分支和已访问面板实例，切换仓库时不得重置已加载列表。每页默认展示最近 `20` 条；继续加载操作必须位于滚动内容的最后一项之后，存在 `nextCursor` 时显示加载按钮，否则在非空列表末尾明确提示已加载全部提交。提交行必须可点击，并在保持历史标签内容挂载的同时打开独立共享文件审核 Dialog；关闭审核只关闭 Dialog，并保留仓库 Tab、分页和滚动状态。提交文件每页加载 `100` 条，单文件 Diff 只在选中后动态读取和挂载。历史标签与审核 Dialog 必须覆盖加载、失败重试、空状态、Diff 截断提示，以及 `320px` 窄屏无横向溢出和清晰可用的主要触控目标。
- 中栏 Composer 底部的 Project 根路径必须使用带 Tooltip 的可访问按钮；按钮宽度跟随路径内容，不得占满底栏剩余空间，长路径按可用宽度收缩截断；按钮可见高度、文字层级、图标尺寸和 Hover 表面必须与相邻分支控件一致，固定为 `24px` 高、caption 文字和 `12px` 图标。多根 Project 必须在路径左侧紧邻显示同高的主目录选择器，按稳定 `rootId` 切换路径、Git、文件树及全部根级视图；单根 Project 不显示选择器，页头不得重复该控件。路径按钮点击固定使用宿主 `file-manager` 能力打开当前主目录并省略请求 `path`，不得继承全局默认打开应用。能力不可用或打开请求进行中时禁用按钮。
- 中栏 Composer 的根仓库分支菜单必须在本地分支列表后提供“新建分支”，通过共享 Dialog 和自动聚焦的输入框收集 Trim 后名称；提交期间同步单飞并禁止关闭或重复操作，失败时保留输入并由根级 toast 展示 Git 原始错误，成功后使用 Server 返回的完整 Git 状态替换共享 Query 缓存、关闭 Dialog 并通过根级 toast 确认。聚合仓库模式继续只读展示，不提供分支切换或创建入口。Git 状态尚未识别或 `repositoryMode` 为 `none` 时不得显示分支控件，也不得读取分支或 worktree；用户刷新 Project 并重新识别为 Git Project 后必须恢复对应查询与控件。
- 中栏 Composer 的根仓库分支菜单必须同时列出当前仓库的其他 worktree，并提供“新建 worktree”；worktree 使用分支和宿主绝对路径共同标识，创建时允许输入已有或新分支，由 Server 在仓库同级生成唯一目录。创建或切换成功后必须把 Server 返回的独立 Project 写入共享 Project Query 并导航到该 Project，不得修改当前 Project 的 `rootPath` 或复用当前 Task Runtime；分支与 worktree Mutation 共用 Project 作用域单飞锁，聚合仓库模式不提供 worktree 入口。
- 中栏 Composer 的模型与思考量必须使用一个统一紧凑触发器，选项只展示名称和尾部勾选，不展示 Provider 描述。桌面端使用两级菜单，移动端使用单层 Dialog 避免级联菜单越出视口；模型切换必须保留仍受支持的当前思考量，否则回落到目标模型默认值，不得保留独立原生下拉框。选择器必须支持键盘、Escape、外部点击和视口碰撞处理，并在工作台移动断点保持清晰可用的触控高度；审批、沙箱、模型与提交操作必须在同一行完整展示，不得使用固定窄宽度裁切当前值，纯图标操作宽度不得低于 `24px`。审批、沙箱、模型与思考量切换成功时必须静默，失败时继续通过根级 toast 展示原始错误。
- Web 不提供登录路由或账号控件；Provider 资源不可用时展示 `codex login` 指引和 Query 重试操作，不调用账号接口。
- `shared/components/agent` 由项目完整维护 Agent 工作台复合组件源码；公开 Props 只服务真实调用方，样式、基础控件和本地化文案统一使用项目设计 Token，不保留外部组件库命名、registry 配置或兼容导出层。
- Task Timeline 与源码预览调用方必须通过轻量 `LazyMessageResponse` 边界加载 Markdown；加载期间完整展示保留换行的原文，重型 `MessageResponse`、Streamdown、Shiki 和语言 Grammar 不得静态进入调用方 Chunk。
- Task Timeline 的流式 Markdown 代码块必须限制在 Assistant 消息的可用宽度内，长代码不得让中栏会话容器产生横向滚动；Playwright 回归必须同时覆盖长代码渲染与代码复制，并断言会话容器的 `scrollWidth` 不超过 `clientWidth`。
- Task Timeline 的流式 Markdown 在收到表头、分隔行和首个数据行后必须立即渲染语义表格，并随 `message.delta` 增量追加后续行，不得等待 Turn 结束；自定义 Remark 插件链必须保留 Streamdown 默认 GFM 插件，Playwright 回归必须使用至少两个真实 Delta 验证表格成形和新增行。
- 通用 `Button`、`Input`、`Textarea`、`Tooltip`、`Dialog`、`DropdownMenu`、`ContextMenu` 和 `ButtonGroup` 必须复用 `shared/components/core` 的项目基础组件；Radix 只作为结构、行为和可访问性底层能力，`shared/components/core` 必须通过 `--ui-*` 驱动的 `brand`、`control`、`panel`、`foreground` 等项目 Token 提供完整默认视觉。Feature 的 `className` 只承担页面布局、定位和响应式尺寸；颜色、字号、字重、圆角、阴影及交互状态必须由项目组件默认值或显式 variant/size 提供。嵌入复合控件的输入必须使用显式 `embedded` 变体，checkbox、radio、hidden 等专用语义不得借用普通文本 `Input`。`tailwind-merge` 必须登记 `caption`、`meta`、`label`、`body-small`、`body`、`heading`、`title`、`display` 等项目 `text-*` 字号 Token，避免与文字颜色类冲突时误删排版。Dialog 必须保留 Portal、焦点圈定、Escape、backdrop 和关闭后焦点恢复；Tooltip 必须使用应用级 Provider 并限制在视口安全边距内；Dropdown Menu 与 Context Menu 的 Portal、视口碰撞、键盘导航、Escape、外部点击和焦点恢复必须交由 Radix 管理，Feature 不得重复实现坐标计算或全局事件监听。
- Button 内容默认居中；全宽导航、列表命令和侧栏入口必须显式使用 `contentAlign="start"` 保持左对齐，不能用只影响文字行盒的 `text-left` 代替 flex 主轴对齐。
- 父级已经持有 hover、selected 或 focus 表面的复合控件，其内部 Button 必须使用 `variant="embedded"` 和 `size="embedded"`，不得叠加默认 Button 的背景、阴影、固定高度或水平 padding；父级必须是该行唯一的交互表面。
- 所有 Lucide 图标必须在全局 `base` 层使用 `16px` 默认尺寸，禁止任何未约束图标回退到 Lucide 原生 `24px`；`size-*` 只用于紧凑控件或明确的语义尺寸，并必须覆盖全局默认值。共享组件必须统一约束其内部图标，业务调用方不得逐个修补组件内置图标。
- 所有 Button 内的 SVG 图标必须由共享 `Button` 尺寸契约统一约束，禁止依赖 Lucide 默认 `24px`。`icon-sm` 内图标固定为 `14px`，其他未显式覆盖的 Button 图标固定为 `16px`，触控目标放大不得同步放大图标；Button 必须统一设置 SVG 的 `shrink-0` 与 `pointer-events-none`。业务组件只在非 Button 图标或经设计明确的特殊尺寸下使用 `size-*`，Button 内图标不得重复声明常规尺寸。带图标的 link Button 必须保持单行 `inline-flex` 对齐，不得出现图标与文字拆行。
- `Select` 必须在共享层约束全部内置 SVG：Trigger 默认图标固定为 `16px`，`toolbar` 尺寸固定为 `24px` 高、caption 文字和 `12px` 图标，Item 及选中标记固定为 `14px`，滚动图标固定为 `16px`。业务组件选择语义尺寸后不得重复声明同一套高度、间距、文字和图标尺寸；浏览器回归必须检查 Trigger 和选中标记的实际计算尺寸，而不只检查类名。
- Web 应用自有文案必须通过按功能拆分的 i18next 命名空间提供 `zh-CN` 与 `en` 资源，完整句子使用语义 key，数量和真实运行时值使用插值；用户消息、Assistant 输出、Command、Tool/Activity 原始名称、Plan 原文、路径、分支、文件名、Skill/MCP 名称、模型标识和服务端描述必须原样展示。Codex 设置英文术语以官方文档为准，不从中文反向翻译。

- Inspector“变更”页签直接挂载提交面板，依次提供直属子 Git 项目选择、message 生成与编辑、commit/commit+push 分段操作，以及按 staged 与 unstaged 分组的 Project 相对文件树；不得显示当前分支、当前分支历史、`GitHistoryList` 或提交审核入口。聚合直属子仓库模式默认选择排序后的第一个 Git 项目；切换 Git 项目必须保持面板和仓库选择器持续挂载，只更新提交内容，并清空旧文件选择、message 和 Mutation 状态。生成 message、commit 与 commit+push 只能携带同一仓库的相对路径和 `snapshot`；完整成功后保留“变更”标签并通过应用根级 toast 提示对应结果，commit 成功但 push 失败或未配置上游时保留 commit SHA 与部分成功状态。提交完成后必须失效当前 Git 项目的状态与历史 Query。
- 提交面板必须固定在 Inspector 剩余高度内且自身不得滚动；提交信息保留换行内容，但输入区域固定为一行可视高度并允许内部纵向滚动。生成 message 使用输入框最右侧的纯图标按钮并通过 Tooltip 提供完整名称；长文件列表只在文件树区域内部滚动，staged 或 unstaged 没有文件时不得渲染对应分类。没有直接文件且只有一个子目录的连续目录链必须合并为单一路径节点；文件复选框位于文件名左侧，单击文件行打开独立单文件 Diff Dialog，只有复选框改变提交选择；文件名与状态图标按新增、修改、删除使用成功、警告、危险语义色。桌面与 `320px` 窄屏都必须验证无整体纵向滚动和横向溢出。
- 运行中的 Turn 必须用 `file_change.updated` 原位更新对应的 `file_change` Item；Item 进入 `completed` 后立即逐文件展示文件名、增删行统计和可点击的单文件 Diff 入口，不能建立第二套 Turn Diff 提示。统一 `AgentFileChange.diff` 必须已经是 canonical Unified Diff，Web 只按补丁正文统计和渲染，不得感知 Codex 原始 `Add/Delete` 内容格式。Turn 结束后改为在回复末尾聚合全部已完成文件变更，以卡片展示去重文件数和总增删行，不能同时保留运行态条目造成重复。单击 Timeline 流式输出中的文件必须在 Inspector 末尾的“文件”标签打开单文件 Diff，与流式消息中的源码和图片共用同一选择并原位替换；关闭标签后立即清理选择。Inspector“项目”文件树和“变更”标签中的单文件 Diff 继续使用独立 Dialog，且不得切换当前 Inspector 标签。“审核”继续打开同一组文件的连续审核弹窗。连续审核必须提供明确的当前位置、上一个/下一个按钮、左右方向键和首尾禁用状态，并支持 Escape 与 backdrop 关闭。连续审核右栏必须按 Project 相对路径使用本地 `FileTree` 展示变更文件；没有直接文件且只有一个子目录的连续目录链合并为单一路径节点，文件节点保留增删统计和当前选中状态。变更文件导航在桌面端打开弹窗时默认展开，在工作台移动断点下默认收起，两端均通过可访问图标按钮展开或收起；移动端展开时从右侧覆盖审核内容，不得压缩 Diff 宽度。单文件 Diff 面板、单文件 Diff Dialog 与连续审核弹窗的根网格不得被 Diff 固有宽度撑出视口。
- 交互控件使用语义化元素并提供可访问名称、键盘行为和明确状态。
- Approval 使用 `Confirmation` 提供 Allow、Deny 和可用的 Session 级决策；进入已有待审批 Task 或当前 Task 新增审批时，队首可操作请求的“允许”按钮必须自动聚焦，让用户可直接按 Enter 确认；网络审批必须明确显示目标 Host 与协议，不能依赖命令文本表达授权对象；细粒度权限审批必须展示请求的网络开关、文件系统访问模式与路径，允许按网络和文件系统类别选择授权子集，并分别提供 Turn 与 Session 作用域；命令审批的 `additionalPermissions` 展示同一规范化权限明细但不改变原有决策操作；User Input 的选择、确认和短文本分别使用 Radio、可切换 Button 和 Input，提交回答使用主色按钮，提交开始后立即禁用重复操作，响应确认后在同一 Turn 中显示用户回答。MCP Elicitation 的标准表单必须按归一化字段渲染语义化控件并支持窄屏触控，URL 交互只允许在新标签页打开经 Provider 校验的 `http` 或 `https` 地址；未协商的扩展表单不得渲染原生 Schema 或提供接受操作，只允许拒绝或取消。
- 可能位于裁剪容器或视口边缘的 Tooltip 必须脱离局部层叠上下文渲染，并在桌面与窄屏中自动翻转、限制到视口安全边距；同时验证 Hover 和键盘焦点行为。
- `shared/styles/globals.css` 是颜色、字体、间距、圆角、阴影、动效和固定布局尺寸的唯一设计 Token 来源；组件使用语义化 Tailwind Token，不散落视觉字面值。
- 浅色与深色主题在同一语义 Token 中使用 `light-dark()` 定义，`data-theme` 只切换 `color-scheme`，禁止复制整套主题变量。
- 颜色模式提供 `system`、`light` 与 `dark`，默认使用 `system` 并跟随系统外观变化；使用版本化浏览器存储保存并在 React 挂载前同步到根节点。设置 Dialog 中选择颜色模式只更新本地草稿，必须在全局设置保存成功后才持久化并应用；取消或保存失败不得改变当前主题，颜色模式本身不进入 Agent 设置 API。
- 界面语言只提供 BCP 47 标签 `zh-CN` 与 `en`，默认和生产回退为 `zh-CN`；使用独立版本化浏览器存储保存，在 React 挂载前初始化并同步 `<html lang>`。设置 Dialog 中选择语言只更新本地草稿，必须在全局设置保存成功后才持久化并应用；取消或保存失败不得改变当前语言，语言本身不进入 Agent 设置 API。
- 系统通知开关使用独立版本化浏览器存储，默认开启且不进入 Agent 设置 API；关闭时不得请求通知权限或发送系统通知。设置 Dialog 中切换通知只更新本地草稿，必须在全局设置保存成功后才持久化并应用。
- 主题色固定为浅色 `surface #ffffff`、`ink #111111`、`brand #006aff`、`diffAdded #28a948`、`diffRemoved #eb001d`，深色 `surface #181818`、`ink #ffffff`、`brand #339cff`、`diffAdded #40c977`、`diffRemoved #fa423e`；Skill 展示统一复用 `brand`，不维护独立颜色；浅色大面积区域保持纯白，普通文字使用 `450` 字重，不添加固定浅灰底。
- 工作台区域优先使用材质背景、淡阴影和留白区分层级，不使用贯穿面板的高对比边框；视口进入覆盖模式时关闭已打开的桌面面板。左右栏的打开状态仅由各自工具栏按钮、窄屏遮罩或响应式视口变化控制，任何情况下都不得由 Escape 键关闭。桌面常驻布局必须提供可拖拽且支持方向键的语义化分隔线，左栏宽度限制为 `220px` 至 `400px`，右栏最小宽度为 `320px`、最大宽度为左栏之外剩余空间的一半；窄屏覆盖模式不显示分隔线。
- 永久 Sidebar 和 Inspector 使用连续同色背景，仅在其纵向边界添加低对比单像素分隔；三栏标题行使用相同高度并保持文字、图标垂直居中，侧栏顶栏不与下方内容分隔，主内容 Toolbar 的单像素底部分隔与左栏搜索框、右栏 Tab 的顶部对齐。不使用模糊或多层重阴影，浮动阴影只用于 Composer、弹层和独立表面。
- 视觉系统变更使用 Playwright 检查 computed style、桌面与移动溢出、窗口缩放和控制台错误。
- 项目组件只能在 `shared/components/core` 或 `shared/components/agent` 内直接维护源码，并同步更新行为、可访问性与视觉测试；禁止重新引入外部 registry、preset、组件生成配置或旧目录兼容层。
- 紧凑 Git 历史区域的“加载更多”按钮必须使用小尺寸并占满分页容器的可用宽度；工作台移动断点下仍必须保持清晰可用的触控高度。
- 只有形成稳定复用模式后才写入本规范。
