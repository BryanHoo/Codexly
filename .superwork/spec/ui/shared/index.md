# 共享 UI

`@codexly/ui` 存放 Web 与桌面端视觉和交互一致的 React 控件。各端现有组件路径可用薄导出维持调用点，但组件实现只保留在 `packages/ui/src/`。

- 基础控件从 `@codexly/ui/core/*` 导入；Agent 展示组件只在平台行为拆出后从 `@codexly/ui/agent/*` 导入。
- Tooltip 不因获得或恢复焦点自动打开；共享 Trigger 保留业务焦点回调，仅阻止 Radix 的焦点打开行为，鼠标悬停仍展示。承载正文的自定义备注提示需支持点击及键盘主动查看。
- Composer 权限与沙盒使用共享 `CompactSelector` 锚定下拉菜单；触发器与模型、思考量保持一致，支持窄屏标签截断和视口碰撞边界，不使用原生 select 弹层。
- 文件打开、下载、Markdown 链接、通知和翻译由调用方提供。公共包不引入 Tauri API、Web 客户端或应用内 feature 代码。
- 新建项目表单共用 `core/new-project-dialog.tsx`，父目录选择切换同一模态层并保留名称；目录创建与项目注册分开，注册失败只重试添加，同名目录须明确确认复用。Web 的文件系统操作面向服务器，须展示主机信息并验证移动端布局。
- 两端 `globals.css` 从应用 `src` 扫描 Tailwind 类，保留 `packages/ui/src` 与第三方组件的显式扫描，并排除测试文件；不得仅扫描 `.tsx`，排版类也可能定义在 `.ts` 中。
- Web 对外可读取的 `--color-brand` 与 `--color-control-hover` 通过 `@theme inline static` 保留，不能依赖测试源码使变量进入生产 CSS；用主题 E2E 校验浅色和深色的实际解析值。
- 消息附件、项目图片和壁纸原图共用 `core/image-preview`，翻译由各端传入；手势引擎仅在预览挂载时加载。预览支持容器内缩放、拖动、双指手势和复位，切换资源或容器尺寸变化时恢复适配；捏合后的触摸拖动不得误判为双击。用 `desktop/src/shared/components/core/image-preview.browser.test.tsx` 验证 Chromium、WebKit 和移动端窄屏。
- 聊天 Markdown 的本地图片共用 `core/message-markdown-image`；文件链接规范化产生的相对路径、Windows 盘符及 UNC 标记须先还原，再通过任务所属工作目录的图片接口读取，禁止将本地路径直接作为网页地址。Web 使用受控文件 URL，桌面复用原生缓存与 asset 通道；普通任务未绑定 `workspacePath` 时使用所属项目的根选择，worktree 绑定目录始终优先；历史回放与分屏不能借用其他活动项目目录，任务切换后丢弃旧异步结果。图片不以 Base64 消息正文传输。回归见两端 `message-response-images.test` 与共享 `markdown-image-source.test.ts`。
- 流式 Markdown 的树形渲染与文本揭示动画放在 `agent/streaming-markdown`，两端引入其共享样式；稳定前缀不能因追加而重挂，图表和自定义插件不得被普通代码快路径替代。
- 验证边界使用 `apps/web/src/shared/components/shared-ui-boundary.test.ts`、根目录 `pnpm lint:architecture`，并分别运行 Web 与桌面构建。

- PDF 文件链接、附件和文件树共用 `core/pdf-preview` 原生预览；用 `navigator.pdfViewerEnabled` 检测能力，缺失时保留显式打开动作。附件点击后才加载，关闭后卸载；不引入 PDF.js 或 Base64 整文件传输。桌面只开放校验后的单文件 asset scope，独立预览窗口同时授权读取和打开命令。

- 分屏输入区域共用 `core/split-composer`，新建任务的草稿窗口默认展开，已有任务默认收起，各窗口可独立手动切换；恢复单窗口或移动端时自动展示。分支、项目路径和上下文底栏始终可见，展开/收起按钮放在该底栏。保留编辑器 DOM、草稿、附件和队列，隐藏区不可聚焦；待回答问题及可用的停止入口不得被收起遮挡。文件引用、底栏草稿恢复应唤起输入框；无底栏的定时任务编辑器不参与收起。
- 分屏输入框收起时，底栏通过共享 `core/composer-model-status` 显示当前解析后的模型与思考量，只提供文本，不提供配置操作；剩余宽度不足时整组隐藏，空间恢复后重新显示。展开输入框或回到单窗口时移除摘要，验证长模型名、窄栏、拉宽恢复及草稿保留。

- 左右栏属于工作区外层，只有中栏参与分屏。右栏共用 `core/split-inspector` 的开关及挂载位置，活动窗口通过 [React Portal](https://react.dev/reference/react-dom/createPortal) 提供右栏内容并保留其任务回调；不得为右栏另建任务订阅。非活动窗口停用右栏专属查询，分屏切换时保留各自文档/标签及全局面板宽度。左栏高亮和 `aria-current` 以活动窗口身份为准，不能让未改变的 URL 再激活原任务。
- 用户消息快捷目录通过 `core/timeline-navigation-host` 定位到所属窗口，采用窗口内绝对定位及相对高度；禁止使用全局首个 `.workbench-shell` 或视口固定定位。回归检查四屏目录互不重叠、右栏切换内容、侧栏唯一激活项、收起状态及草稿保留。
- 分屏时左栏普通任务点击由工作区接管：目标未打开则原位替换聚焦窗口，已打开则只切换焦点，禁止退出分屏或删除原窗口；其余窗口的顺序、草稿和挂载身份保持稳定。单窗口、移动端及修饰键打开链接继续使用原有导航行为。回归覆盖四屏满额替换、重复选择及跨项目任务身份。
- Web 通知与桌面原生任务跳转沿用分屏任务选择规则，按点击时的最新焦点处理，禁止通过路由切换重置分屏。工作区未挂载、单窗口及移动端回退到平台路由；卸载工作区必须清理导航监听。回归覆盖项目与临时聊天通知、四屏布局及相邻草稿保留、已打开任务聚焦和导航回退。
- 全局搜索（含历史定位）、任务看板、定时任务记录和宠物任务提示沿用上述任务导航桥；未接入桥的任务路由变化也只能替换聚焦窗口，保留其他窗口及分割比例。搜索关闭后不得把焦点还给非活动窗口或已移除的输入框，应恢复最新活动窗口且不改变滚动位置。删除或归档成功后按返回时的任务身份关闭对应窗口，与原 URL 或当前焦点无关；目标已不在工作区时不得通过旧 URL 重置其他聊天，失败不关闭窗口。分屏收敛后的最后任务被删除时显示独立空草稿，普通单窗口和移动端保留平台导航。使用 `split-workspace-navigation.fixture.tsx`、`split-workspace-selection.test.ts` 与 `use-task-deletion.test.tsx` 验证窗口数、活动身份、相邻输入框和草稿保留。
- 分屏新建任务同样替换聚焦窗口，包括全局入口、项目/聊天分组加号、桌面快捷键和 worktree 创建。空聊天使用独立草稿身份和 Composer 存储范围，不能伪造 taskId 或提前创建服务端任务；范围切换及首次发送后只替换所属窗口，旧草稿的迟到结果不得覆盖新草稿。回归覆盖同项目多草稿、四屏新建、草稿转任务和关闭后返回结果。
- 任务标题栏的加号在单窗、分屏与 Web 窄屏常显，放在右侧操作区最前面；两端共用 `core/workbench-new-task-button`。新任务默认归属按钮所在窗口的项目，分屏只替换该窗口，单窗沿用项目或临时聊天的草稿路由；提供可访问名称和悬停提示。
- 中栏空白处右键菜单与 `⌘/Ctrl + Alt + 方向键` 共用方向分屏动作，按目标窗口的上、下、左、右侧打开同项目独立草稿，最多四屏；正文字符、选区和交互控件保留原有右键行为，对话框与菜单打开时不响应分屏快捷键。方向切分不得改变现有窗口挂载身份，任务替换保留位置、关闭后兄弟窗口填满空缺；普通空聊天页保留原有草稿存储与单窗口首次发送导航。回归覆盖方向坐标、草稿隔离、四屏上限、替换与关闭、空聊天导航及空白命中判定。
- 分屏宽高通过共享分割线连续调整；嵌套分割线只改变所属区域，任务替换与关闭相邻窗口保留其余比例。拖动预览按浏览器帧合并样式更新，松开才提交工作区状态，禁止因拖动重挂聊天或刷新任务订阅；取消、失焦、布局变化及卸载必须清理指针捕获和遮罩。分割线支持键盘调整并限制极端尺寸；移动端继续展示活动窗口。回归覆盖宽高拖动、局部切分、最小尺寸、取消恢复、草稿及 DOM 身份保留、关闭后的区域填充。
- 分屏操作、布局状态与全局焦点分别提供 Context；窗口内导航、草稿和右栏桥接仅订阅所属窗口，外层入口按需订阅全局状态。未变化窗口的 Context 值及侧栏操作引用保持稳定；切换焦点只更新原活动窗口与新活动窗口，调整布局不应额外执行聊天组件及 Hook。稳定操作仍读取最新窗口集合，单窗口和移动端保留导航回退。使用 `desktop/src/shared/components/core/split-workspace.browser.test.tsx` 验证 Web 与桌面模式的渲染次数、操作引用、输入框身份和草稿保留。

- 项目文本预览内直接编辑共用 `core/inline-text-file` / `core/text-file-editor`，不使用编辑弹窗、工具栏或查找替换；编辑器和语言按需加载，输入文本不进入 React state / Query 缓存。失焦串行自动保存并由宿主 toast 反馈，保存期间输入继续补存；失败草稿在当前窗口保留，重开恢复；成功后解除草稿保护，已保存会话进入按客户端隔离的 16 条目 / 64 MiB 估算预算 LRU 缓存。分屏重挂前只检查磁盘修订标记，变化才读取全文；合并在途读取，并复用文本树、选择和滚动快照；已保存会话保留撤销/语言状态，闲置未保存草稿释放历史、解析和视图绑定。输入按 UTF-8 字节数限制为 2 MiB，正文超过 256 KiB 时同步停用解析并在缩小后恢复。所有客户端共用 16 文件 / 32 MiB 正文预留预算，满额只读回退，已有草稿可恢复；此预算不代表精确堆内存上限。活动会话及未保存草稿不得因闲置预算淘汰。关闭及路由等待保存，卸载销毁 EditorView 并补存，退出保护未保存内容。边界、接口和验证见 [文本文件编辑方案](../../../../docs/text-file-editing.md)。
- 两端文件面板的可编辑正文由共享编辑会话独占读取；加载期间不请求分页或展示旧分页缓存。Markdown 渲染与源码编辑复用同一会话，切换时不重新读取全文；只有不可编辑、超限、编辑器加载失败或缺少项目根目录才使用分页预览。滚动及目标行补页也必须受分页回退条件约束。

- 文本编辑保护不得静默禁用操作：两端共用 `core/text-editor-notice` 在文件面板常驻说明只读/输入受限/保存失败原因与下一步。容量及读取失败提供原位“重试编辑”，期间保留只读内容；保存失败提供“重试保存”，成功后解除原因。输入超限说明原内容未变、仍可继续编辑；高亮降级明确仍可编辑和保存。文案及可访问状态保持中英文同步。
