# 后端运行时生命周期

## 规则

- CLI 在根目录 `src` 完成配置解析和运行时装配，包内模块不读取 CLI 隐式状态。
- CLI 在打开业务数据库和启动 Codex 前，使用独立 Worker 持有同数据目录的 SQLite 独占实例锁；锁不随业务 Worker 重建，锁失效必须停止运行，所有退出路径最终释放锁。数据库文件保留不表示仍被占用，不使用 PID 文件猜测崩溃状态。
- Codex App Server 子进程、WebSocket、HTTP Server 和 Worker 都必须在失败、取消和正常退出时释放。
- `better-sqlite3` 同步操作只在独立 `worker_threads` Worker 中执行，Fastify 主线程不直接访问数据库。
- SQLite 操作超时后必须终止状态未知的 Worker，使当前请求明确失败，并重建 Worker 供后续请求恢复，不能让 Repository 永久停留在 closed 状态。
- 以 `project_id` 表示 Task 作用域的持久表必须接纳没有 `projects` 记录的 `temporary` 作用域，不得通过 Project 外键阻断临时任务；真实 Project 删除时需显式清理所属数据。
- 新建无名称 Task 在首次成功启动普通或 Goal Turn 后，只在后台领取一次自动标题生成；计划任务复用同一 Provider 入口。CLI 按需注入 `commitMessageModel` 及其默认值，提示正文最多 1024 个 Unicode 字符，结构化标题最多 36 个字符。辅助 Thread 隔离 MCP、工具和用户可见事件，60 秒超时或失败后中断并退订；任务删除、释放与项目关闭取消相关生成。写回前校验 Task/Project 身份，并与手动命名共用锁，已有名称不覆盖，失败保留消息预览。
- Agent Event 保持顺序、断线恢复和取消语义；跨层事件结构由 `@codexly/protocol` 定义。
- 新增长驻缓存、队列或事件流时定义容量上限、所有权和关闭行为。
- 批量删除归档任务由 Node 先收集全部归档分页并按 ID 去重，再以最多四项并发删除；列表跨作用域、重复游标、超过 1000 页或 10000 个目标时必须在删除前失败。删除前重新校验任务归属，单项失败不阻止其他目标，返回成功与失败数量。
- 实时 Skill 展开在 Provider 发布事件前按历史快照同一规则合并，向所有订阅者发送原用户 ID 的完整消息；带附件的独立输入不能作为纯 Skill 展开吞并。仅缓存运行回合的末尾用户项及相邻屏障，最多 128 项，单项 JSON 不超过 65536 字符、合计不超过 1048576 字符；超限保留独立消息，终态、任务释放和运行时关闭时清理。旧快照不能跨过已收到的助手消息重新建立相邻关系。
- 消息身份表归 `TaskRuntimeState` 所有，任务清理和运行时关闭时释放；限制为 128 个回合、每回合 256 条消息、每消息 256 个别名，比较文本每条不超过 16384 字符、总计不超过 1048576 字符。优先淘汰已结束回合；超预算停止内容推断而非截断后匹配。内容匹配要求角色、阶段相容且双向唯一，身份不承诺跨进程持久化。
- 定时任务使用持久快照和单个最近期限定时器调度；重启时修复中断运行，重复周期合并错过触发且禁止同任务重叠执行。
- RRULE 在解析前限制输入长度和候选组合数量；所有日历遍历必须放入有时间预算、可终止且并发有界的 Worker，超时后终止线程并释放名额。预览与自动调度共用异步入口，不能用普通请求超时代替同步计算中断。
- 定时任务状态持久化成功后经全局 WebSocket 推送轻量失效通知，自动到期和手动执行共用链路；连接遵守会话过期、心跳及背压限制，关闭时释放订阅与计时器，未变化的调度快照不重复写库或推送。
- 队列消息调用 Provider 前必须原子持久化执行标记；成功结果用于恢复清理，未知结果禁止自动重复投递。测试覆盖删除失败、结果写入失败和重启恢复。
- 手动 `/queue/start` 按服务端当前快照选择 start 或 steer，读取持久队列正文而非客户端副本；两条路径共用执行占用、结果恢复、附件转移与删除流程。steer 结果未知时禁止回退 start。自动出队发现已有运行回合时保持队列，不转为 steer；编辑屏障在后端强制校验。覆盖并发幂等请求、运行状态变化及引导成功后的清理失败。
- 队列更新为 `queued` 时，Node 在同一任务锁内保存内容、保留附件并尝试恢复队首；不得跳过更早的排队项或编辑屏障，运行中不得自动 steer。更新响应表示已保存的输入，实际剩余队列通过查询及 `queue.changed` 同步；执行结果未知的再次更新返回 409，不能重复投递。
- 排队附件交给运行中的 Turn 后由 Turn 生命周期持有；后续删除原队列项只解除队列所有权，不得删除已提交附件。
- 调度运行锁仅在启动记录落库成功后占用；自动调度写入失败需延迟重试，完成结果写入失败只重试持久化，不重新启动任务。
- 定时运行以 runId 生成独立持久提交 Key，复用 Core 提交状态机。`unknown` 保留 Task 关联并暂停后续执行，禁止立即运行和重新启用；`cleanup_pending` 只重试已确认结果落库和收尾，禁止编辑或删除，重启继续恢复。不得把中断或超时无条件判为失败，也不得清理结果未知的运行中附件。
- 定时任务引用的临时附件必须将文件内容持久化，并在每次运行前恢复到新的 AttachmentStore；任务快照、附件替换和删除关联资源必须通过同一个 Worker 请求在一个 SQLite 事务中提交，提交成功后才更新服务内存并通知订阅者。附件准备仅负责读取和校验，禁止用事后补偿写入模拟事务；回归测试覆盖 SQL 失败、重启恢复和通知时的跨连接可见性。
