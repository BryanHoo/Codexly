# Feature Implementation Plan

**Goal:** 为 Codexly Web 添加可持久化切换的简体中文与英文界面，并按 Codex 官方术语本地化应用自有文案而不改写 AI 或外部动态内容。

**Suggested Spec Reads:**

- `.superwork/spec/guides/index.md` — 约束全仓验证与依赖管理。
- `.superwork/spec/frontend/component-guidelines.md` — 约束设置 Dialog、Composer、Timeline 与 AI Elements 行为。
- `.superwork/spec/frontend/state-management.md` — 约束浏览器偏好与服务端状态边界。
- `.superwork/spec/frontend/quality-guidelines.md` — 约束可访问性、测试与用户流程验证。
- `docs/web-design.md` — 约束工作台界面结构和状态语义。
- `.superwork/prd/2026-08-02-web-i18n-design.md` — 固定语言边界、术语来源与非目标。

**Architecture:** 使用 `i18next` 与 `react-i18next` 建立按功能命名空间拆分的静态资源；用版本化 `localStorage` 保存 BCP 47 语言标签，在 React 挂载前初始化并同步 `<html lang>`。组件仅翻译应用拥有的 UI 文案，AI/用户消息、命令、路径和服务端动态内容保持原样。

**Tech Stack:** TypeScript、React 19、i18next、react-i18next、Vite 8、Vitest、Playwright、pnpm。

## Global Constraints

- 默认语言为 `zh-CN`，支持语言固定为 `zh-CN` 与 `en`，生产回退语言显式使用 `zh-CN`。
- 英文使用 Codex 官方术语 `Reasoning effort`、`Approval policy`、`Sandbox`、`Minimal`、`Low`、`Medium`、`High`、`Extra high`。
- 不翻译用户消息、Assistant 输出、Command、Tool/Activity 原始名称、Plan 原文、路径、分支、文件名、Skill/MCP 名称、模型标识和服务端描述。
- 保留 `Codexly`、`Codex`、`Agent`、`AI`、`MCP`、`Git`、`Turn`、`Skill`、`Token`、`Diff`、`CLI`、`Runtime` 等专有名词。
- 完整句子进入资源文件，仅对真实运行时值插值；数量文案使用复数 key，日期和数字显式使用当前 locale。
- 不启动开发服务器，不修改 Server 或 Protocol，不保留旧硬编码文案双轨逻辑。
