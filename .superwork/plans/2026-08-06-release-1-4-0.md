# Feature Implementation Plan

**Goal:** 将根 npm 包更新并发布为 `1.4.0`，完整记录 `v1.3.0` 之后的变化，并通过 `v1.4.0` 标签发布 npm 包和 GitHub Release。

**Suggested Spec Reads:**

- `.superwork/spec/guides/index.md` — 定义发布结构、包校验和完整验证要求。
- `docs/releasing.md` — 定义版本、标签、npm 和 GitHub Release 的发布顺序。

**Architecture:** 保持单一公开根包模型，只更新根包版本元数据与发布文档；验证本地制品后提交并推送 `main`，再推送匹配标签触发现有 Release workflow。

**Tech Stack:** pnpm 11、Node.js 24、Git、GitHub Actions、GitHub CLI、npm registry

## Global Constraints

- 仅发布根包 `@bryanhu/codexly`，内部 `@codexly/*` Workspace 包继续保持私有。
- 发布版本和标签必须分别为 `1.4.0` 与 `v1.4.0`。
- 发布前必须通过 `pnpm check` 和 `pnpm test:e2e`，不得启动开发服务器。
- 发布提交必须遵循中文 Conventional Commits，并包含必填 scope。

### Task 1: 更新 1.4.0 发布元数据与文档

**Files:**

- Modify: `package.json`
- Modify: `CHANGELOG.md`
- Modify: `docs/releasing.md`

**Interfaces:**

- Consumes: `v1.3.0..HEAD` Git 提交历史与现有单包发布流程
- Produces: `@bryanhu/codexly@1.4.0` 元数据、1.4.0 更新日志与发布说明

**Behavior:**

- 将公开根包版本更新为 `1.4.0`，按新增、优化、修复和工程分类完整归纳 `v1.3.0` 后的用户可见与发布相关变化，并使发布文档示例匹配本次版本。

**Stop Conditions:**

- 如果发现除根包外还有公开 Workspace 包，停止并重新确认版本范围。
- 如果 `1.4.0` 已存在于 npm、远端标签或 GitHub Releases，停止以避免复用已发布版本。

- [x] **Task Status:** completed

Run: `node --input-type=module -e "import manifest from './package.json' with { type: 'json' }; if (manifest.version !== '1.4.0') process.exit(1)" && rg -n '1\\.4\\.0|v1\\.4\\.0' CHANGELOG.md docs/releasing.md`

Expected: 根包版本为 `1.4.0`，更新日志和发布文档均包含匹配版本与标签。

### Task 2: 验证发布制品与端到端流程

**Files:**

- Test: `package.json`
- Test: `tools/verify-package.mjs`
- Test: `tests/e2e/`

**Interfaces:**

- Consumes: 更新后的根包版本和构建输入
- Produces: 可发布 tarball 校验、完整质量门禁与浏览器端到端证据

**Behavior:**

- 执行仓库要求的完整静态、单元、性能、构建、制品和端到端验证。

**Stop Conditions:**

- 如果任何验证失败，停止发布并修复当前变更导致的问题。
- 如果失败来自环境或既有代码且无法安全解决，停止并报告具体阻塞项。

- [x] **Task Status:** completed

Run: `pnpm check && pnpm test:e2e`

Expected: 两个命令均以退出码 0 完成，发布 tarball 不包含未解析协议或源码映射。

### Task 3: 创建并触发 1.4.0 发布

**Files:**

- Modify: Git `main` branch
- Create: Git tag `v1.4.0`
- Create: GitHub Actions Release workflow run
- Create: GitHub Release `v1.4.0`
- Create: npm package `@bryanhu/codexly@1.4.0`

**Interfaces:**

- Consumes: 已验证的发布提交、`origin` remote 与发布凭证
- Produces: 远端 `main`、`v1.4.0` 标签、GitHub Release 和公开 npm 版本

**Behavior:**

- 使用符合项目规则的发布提交，推送 `main` 和带注释标签 `v1.4.0`，等待 Release workflow 成功并确认 npm 与 GitHub Release 均可查询。

**Stop Conditions:**

- 如果远端分支在提交后出现非快进变化，停止并报告，不强制推送。
- 如果 GitHub Actions 或 npm 鉴权失败，停止并报告失败 Job，不绕过发布工作流手工发布。

- [x] **Task Status:** completed

Run: `gh run list --workflow release.yml --limit 1 && gh release view v1.4.0 && pnpm view @bryanhu/codexly@1.4.0 version`

Expected: 最新 Release workflow 成功，GitHub Release `v1.4.0` 存在，npm 返回版本 `1.4.0`。
