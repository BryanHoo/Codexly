# Codex 0.149.0 Upgrade Implementation Plan

**Goal:** 将项目内置 Codex 升级到 `0.149.0`，并依据 OpenAI 官方文档与目标 CLI 生成的真实 App Server Schema 对齐现有 Provider、统一事件和界面逻辑。

**Suggested Spec Reads:**

- `.superwork/spec/guides/index.md` — 约束依赖升级、Schema 基线和完整验证。
- `.superwork/spec/backend/runtime-lifecycle.md` — 约束 App Server、Notification、Task 归属和审批事件。
- `.superwork/spec/backend/quality-guidelines.md` — 约束严格运行时校验、日志和契约测试。
- `.superwork/spec/shared/directory-structure.md` — 约束 Protocol、Core、Provider 和 Web 的依赖方向。
- `.superwork/spec/shared/quality-guidelines.md` — 约束 Provider 专有字段、统一事件和消费者同步。
- `.superwork/spec/frontend/type-safety.md` — 约束 Web 只消费统一 Protocol。

**Architecture:** 继续由 `provider-codex` 独占 Codex 原生协议边界；用 `@openai/codex@0.149.0` 的 `--experimental` 生成器刷新完整 Schema 基线。严格校验现有消费链路新增的 `Thread.projectId` 与 `agentMessage.delivery`，将 Guardian 严格审核通知映射为 Provider 无关提示；Codex 原生 Project API 与通知不进入 CodeAgent 自有 Project 契约，并通过通知分类与初始化 opt-out 显式隔离。

**Tech Stack:** TypeScript 6、Node.js 24、pnpm Workspace、Codex App Server JSON-RPC v2、TypeBox、Vitest、Playwright。

## Global Constraints

- 使用项目既有 `pnpm@11.15.1`，所有 Python 命令使用 `python3`。
- 以 OpenAI 官方 0.149.0 更新日志、App Server 文档和 `codex app-server generate-ts/generate-json-schema --experimental` 输出为事实来源。
- 只实现 0.149.0 新逻辑，删除 0.148.0 版本绑定和旧 Schema 基线，不增加旧协议兼容分支。
- CodeAgent Project 继续由本地 Protocol、Server 和持久层拥有；不得把 Codex 实验 Project 对象或 ID 泄漏到 Core、Protocol 或 Web。
- 关键协议校验添加简短、清晰的中文注释；生产代码文件不得超过 500 行。
- 保留用户已有未提交改动，不启动开发服务器，不自动提交。
