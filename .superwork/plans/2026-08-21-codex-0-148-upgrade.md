# Codex 0.148.0 Upgrade Implementation Plan

**Goal:** 将项目内置 Codex 升级到 `0.148.0`，并依据官方发布说明与锁定版本生成的真实 App Server Schema 对齐现有 Provider 功能和协议边界。

**Suggested Spec Reads:**

- `.superwork/spec/guides/index.md` — 约束依赖升级、Schema 基线和完整验证。
- `.superwork/spec/backend/runtime-lifecycle.md` — 约束 Codex App Server、Notification 和外部对象映射。
- `.superwork/spec/backend/quality-guidelines.md` — 约束严格运行时校验、日志和契约测试。
- `.superwork/spec/shared/directory-structure.md` — 约束 Protocol、Core、Provider 和 Web 依赖方向。
- `.superwork/spec/shared/quality-guidelines.md` — 约束 Provider 专有字段和统一 Item 契约。
- `.superwork/spec/frontend/type-safety.md` — 约束 Web 只消费统一 Protocol。

**Architecture:** 继续把 `provider-codex` 作为唯一 Codex 原生协议边界；用 `@openai/codex@0.148.0` 自带生成器刷新完整 Schema 基线，只对 CodeAgent 已消费的对象增加严格字段校验和统一映射。新增但未进入现有产品契约的 `thread/queue/*`、`thread/revert` 与诊断 API 明确分类为不订阅，不把实验 Provider 结构透传到 Core、Protocol 或 Web。

**Tech Stack:** TypeScript 6、Node.js 24、pnpm Workspace、Codex App Server JSON-RPC v2、TypeBox、Vitest、Playwright。

## Global Constraints

- 使用项目既有 `pnpm@11.15.1`，所有 Python 命令使用 `python3`。
- 以 OpenAI 官方 0.148.0 发布说明和 `@openai/codex@0.148.0 app-server generate-ts/generate-json-schema --experimental` 输出为事实来源。
- 只实现 0.148.0 新协议，不保留 0.147.0 运行时兼容分支或旧 Schema 基线。
- Provider 原始结构不得越过 `provider-codex`；新增但未被产品使用的方法必须显式分类，不能静默接受。
- 关键协议校验添加简短、清晰的中文注释；生产代码文件不得超过 500 行。
- 不启动开发服务器，不自动提交。
