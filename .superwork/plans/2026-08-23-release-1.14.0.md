# Feature Implementation Plan

**Goal:** 跳过已回退的 1.13.0，发布 Codexly 1.14.0，并同步版本说明、验证证据、npm 包与 GitHub Release。

**Suggested Spec Reads:**

- `.superwork/spec/guides/index.md` — 定义版本、包管理器与发布校验约束。
- `.superwork/spec/backend/quality-guidelines.md` — 约束根发布包的质量门禁。
- `.superwork/spec/frontend/quality-guidelines.md` — 约束用户能力文档与浏览器流程验证。
- `.superwork/spec/shared/quality-guidelines.md` — 约束跨包协议变更的验证范围。

**Architecture:** 沿用 tag 驱动的发布工作流，将根包版本从 1.12.0 直接提升至 1.14.0，按 `v1.12.0..HEAD` 的用户可见变更维护中英文说明和更新日志，通过本地完整门禁后提交并推送 `v1.14.0`，最后核验 GitHub Actions、GitHub Release 与 npm 包。

**Tech Stack:** Markdown、JSON、pnpm、Git、GitHub CLI、GitHub Actions、npm

## Global Constraints

- 使用 `pnpm` 执行项目命令，使用 `python3` 执行 Python 命令。
- 不创建或发布 `1.13.0`；发布 tag 必须与根 `package.json` 的 `1.14.0` 一致。
- 提交信息必须符合仓库要求的中文 Conventional Commits 格式。
- 发布前必须通过 `pnpm check` 与 `pnpm test:e2e`。

### Task 1: 更新 1.14.0 版本与发布文档

**Files:**

- Modify: `package.json`
- Modify: `README.md`
- Modify: `README.zh-CN.md`
- Modify: `CHANGELOG.md`

**Interfaces:**

- Consumes: `v1.12.0..HEAD` 提交记录与现有发布文档结构
- Produces: `release-candidate-1.14.0`

**Behavior:**

- 将根包版本直接提升至 `1.14.0`，准确记录新增能力、优化、修复和工程变化，并使更新日志比较链接从 `1.12.0` 直接指向 `1.14.0`。

**Stop Conditions:**

- 若 npm、GitHub 或远端 Git 已存在 `1.14.0`，停止发布并核对已有产物。

- [x] **Task Status:** completed

Run: `pnpm exec prettier --check package.json README.md README.zh-CN.md CHANGELOG.md`

Expected: 四个发布文件格式检查通过，且版本与文档均指向 `1.14.0`。

### Task 2: 执行完整发布校验

**Files:**

- Test: `package.json`
- Test: `tests/e2e/`
- Test: `tools/verify-package.mjs`

**Interfaces:**

- Consumes: `release-candidate-1.14.0`
- Produces: `verified-release-candidate-1.14.0`

**Behavior:**

- 按项目发布规范执行完整校验，确认源码、浏览器流程和真实 tarball 均可发布。

**Stop Conditions:**

- 任一校验失败时停止提交与 tag，先修复发布阻塞项。

- [x] **Task Status:** completed

Run: `pnpm check && pnpm test:e2e`

Expected: 两个命令均以退出码 0 完成。

### Task 3: 提交并推送 1.14.0 发布 tag

**Files:**

- Modify: Git history on `main`
- Create: annotated Git tag `v1.14.0`

**Interfaces:**

- Consumes: `verified-release-candidate-1.14.0`
- Produces: `remote-release-tag-v1.14.0`

**Behavior:**

- 使用符合仓库规范的中文 Conventional Commit 提交发布文件，推送 `main` 和 annotated tag `v1.14.0`。

**Stop Conditions:**

- 若远端分支出现新提交、工作树包含非本次变更或 tag 已存在，停止推送并重新核对。

- [x] **Task Status:** completed

Run: `git ls-remote --exit-code --tags origin refs/tags/v1.14.0`

Expected: 推送前该命令不存在匹配 tag，推送后远端精确存在 `v1.14.0`。

### Task 4: 隔离 Release 单元测试进程

**Files:**

- Modify: `.github/workflows/release.yml`
- Modify: `.superwork/spec/shared/quality-guidelines.md`
- Modify: `tests/ci-quality-gates.test.ts`

**Interfaces:**

- Consumes: Release workflow `Run quality gates` 与 Vitest 测试目录
- Produces: `isolated-release-quality-gates`

**Behavior:**

- 保留完整发布门禁，使用 Node.js 24，并将 Release 的普通 Vitest 测试按 Web、共享包、Provider、Server 和根测试拆为独立单 worker 进程，避免旧版运行时与长寿命进程中的原生模块崩溃。

**Stop Conditions:**

- 若分组不能覆盖现有全部普通 Vitest 测试文件，停止并修正分组边界。

- [x] **Task Status:** completed

Run: `pnpm exec vitest run tests/ci-quality-gates.test.ts`

Expected: 契约测试确认 Release 保留全部门禁并使用五个互斥测试分组。

### Task 5: 核验自动发布结果

**Files:**

- Test: `.github/workflows/release.yml`
- Test: GitHub Release `v1.14.0`
- Test: npm package `@bryanhu/codexly@1.14.0`

- Produces: 成功的 GitHub Actions run、GitHub Release 与 npm tarball 发布记录

**Behavior:**

**Stop Conditions:**

- 若 workflow 失败或等待外部 Environment 审批，报告具体阻塞状态且不创建替代 tag。
