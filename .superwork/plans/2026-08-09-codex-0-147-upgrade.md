# Codex 0.147.0 Upgrade Implementation Plan

**Goal:** 将项目内置 Codex 升级到 `0.147.0`，以稳定的 `Pinned` Section 替代已删除的 `isPinned` 元数据，并适配新增的 MCP 认证状态与用户输入请求字段。

**Suggested Spec Reads:**

- `.superwork/spec/guides/index.md` — 约束依赖升级、Schema 基线和全量验证。
- `.superwork/spec/backend/runtime-lifecycle.md` — 约束 Codex Thread、Pending Request、MCP 和进程生命周期。
- `.superwork/spec/backend/quality-guidelines.md` — 约束 Provider 外部输入校验和契约测试。
- `.superwork/spec/shared/directory-structure.md` — 约束 Protocol、Core、Provider 和 Web 依赖方向。
- `.superwork/spec/shared/quality-guidelines.md` — 约束 Task 固定与 MCP 统一协议。
- `.superwork/spec/frontend/type-safety.md` — 约束 Web 只消费 Protocol 判别类型。

**Architecture:** 保持现有 Provider 无关的 `AgentTask.pinned` 和固定 Mutation 契约，在 `provider-codex` 边界把 Codex 稳定 `Pinned` Section 映射为布尔固定状态，并用 `thread/section/move` 完成固定与取消固定；同步接纳 `0.147.0` 新增的 `unknown` MCP 认证状态和必填 `isBlocking` 用户输入字段，最后刷新锁文件与版本化 Schema 基线。

**Tech Stack:** TypeScript 6、Node.js 24、pnpm Workspace、Codex App Server JSON-RPC v2、TypeBox、React 19、Vitest、Playwright。

## Global Constraints

- 使用项目既有 `pnpm@11.15.1`，所有 Python 命令必须使用 `python3`。
- 只实现 Codex `0.147.0` 新协议，不保留 `isPinned`、`thread/metadata/update.isPinned` 或 `0.146.0` 兼容分支。
- `Pinned` 状态只识别 Codex 固定 Section ID `01984de2-8f74-7c91-a3b2-5c5e937cf318`；其他自定义 Section 不得误判为固定。
- 固定 Mutation 仍以 Codex 原生持久化状态为唯一事实来源，不恢复本地固定表或双写。
- 关键协议校验添加简短、明确的中文注释，普通自解释代码不堆叠注释。
- 不启动开发服务器，不自动提交。
