# Codex 0.146.0 Upgrade Implementation Plan

**Goal:** 将项目内置 Codex 升级到 `0.146.0`，使用原生 Thread 固定状态，保持项目级 MCP 作用域，并删除重复的本地固定存储。

**Suggested Spec Reads:**

- `.superwork/spec/guides/index.md` — 约束包管理、发布与全局验证。
- `.superwork/spec/backend/runtime-lifecycle.md` — 约束 App Server、Thread、MCP 和 SQLite 生命周期。
- `.superwork/spec/backend/quality-guidelines.md` — 约束 Provider 映射、日志和测试。
- `.superwork/spec/shared/directory-structure.md` — 约束 Core、Protocol 和 Server 依赖方向。
- `.superwork/spec/shared/quality-guidelines.md` — 约束 Task Mutation 和统一协议。
- `.superwork/spec/frontend/state-management.md` — 约束 Task 固定后的 Query/Snapshot 状态同步。
- `docs/architecture-design.md` — 记录 Codex 二进制、Provider 与持久层架构真相。
- `docs/project-structure.md` — 约束 Workspace 与发布包结构。
- `.superwork/prd/2026-08-03-codex-0-146-upgrade-design.md` — 已批准的升级边界和非目标。

**Architecture:** 保持现有统一 HTTP/Web 协议，通过 Core `AgentProvider` 扩展将 Codex `Thread.isPinned` 和 `thread/metadata/update` 接入现有固定流程；Server 不再覆盖 Provider 状态；MCP 列表继续使用带 `cwd` 的项目级生效配置；版本仍通过随包固定二进制和启动门禁锁定。

**Tech Stack:** TypeScript 6、Node.js 24、pnpm workspace、Codex App Server JSON-RPC v2、Fastify、SQLite、Vitest、Playwright。

## Global Constraints

- 使用项目既有 `pnpm@11.15.1`，所有 Python 命令必须使用 `python3`。
- 不为 `0.145.0` 或本地 `task_metadata` 增加兼容、迁移或双写逻辑。
- App Server 初始化继续启用 `capabilities.experimentalApi = true`；不新增 Plugin 或实验功能开关 UI。
- Provider 边界只向统一协议暴露 MCP 名称，不暴露 command、env、URL、工具详情或 Secret。
- 关键协议校验添加简短、明确的中文注释，普通自解释代码不堆叠注释。
- 不启动开发服务器，不自动提交。
