# Web and mobile guide

[Documentation](README.md) · [简体中文](web.md) · [Desktop installation](../desktop/docs/installation.en.md)

The Web server runs on the computer holding your projects. Computers, phones, and tablets access it through browsers. The desktop app runs independently; start a Web server for mobile access to the same host.

## Requirements and startup

The host needs Node.js >=24.0.0. Supported browsers are Chrome / Chromium 116+, Firefox 124+, and Safari 17.4+. Mobile devices need only a compatible browser. The npm package installs Web dependencies and reads agent configuration on the host.

Try without a global installation:

```bash
npx --package @bryanhu/codexly@latest codexly start
```

The default URL is `http://127.0.0.1:3210`; occupied ports are skipped, so use the printed address. Keep the terminal running and press `Ctrl+C` to stop. Follow [agent setup](getting-started.en.md) on first use.

For regular use:

```bash
npm install --global @bryanhu/codexly@latest
codexly
```

`codexly` means `codexly start`. Use `codexly start --no-open` to suppress browser opening.

## Mobile and LAN access

1. Start LAN mode on the host: `codexly start --lan` after global installation, or use the command below.
2. Connect your mobile device to the same trusted LAN and open the printed LAN URL.
3. Enter the access password from the terminal. Do not use `127.0.0.1` on the phone: that refers to the phone itself.
4. Open a host project to follow tasks, send messages, handle approvals, and review files and changes.

```bash
npx --package @bryanhu/codexly@latest codexly start --lan
```

LAN mode listens on network interfaces without opening a host browser. Keep the host awake with the service running. Allow the port through its firewall; guest Wi-Fi or client isolation may block device-to-device connections.

LAN mode uses unencrypted HTTP and is only for trusted networks. Never expose it directly through public forwarding or proxies. `--allowed-host` only extends the Host allowlist; it adds no encryption or authentication.

A random password is generated by default. Restarts invalidate random pairing codes and all sessions. Explicit fixed passwords remain usable, but users must log in again. Autostart saves and reuses its own password.

## Common options

After global installation, use these with `codexly start`. For temporary use, prefix the command with `npx --package @bryanhu/codexly@latest`.

| Option                        | Purpose                                                                                   |
| ----------------------------- | ----------------------------------------------------------------------------------------- |
| `--port <port>`               | Starting port; occupied ports are skipped                                                 |
| `--no-open`                   | Suppress browser opening                                                                  |
| `--lan`                       | Enable trusted LAN access                                                                 |
| `--lan-password <password>`   | Fixed 16–128 character password with uppercase, lowercase, and numbers; requires `--lan`  |
| `--session-ttl <duration>`    | Fixed session lifetime, e.g. `12h`; omitted sessions last until restart; requires `--lan` |
| `--workspace <absolute-path>` | Restrict project roots; repeatable                                                        |
| `--allowed-host <domain>`     | Allow an exact proxy domain; repeatable                                                   |
| `--codex-home <directory>`    | Set Codex configuration/history location; does not move `~/.codexly`                      |
| `--codex-bin <path>`          | Use a compatible external Codex executable; affects Codex only                            |

Quote shell-special characters in passwords. Run `codexly start --help` for complete help.

The bundled Codex CLI is `0.164.0`. External executables supplied through `--codex-bin` or `CODEXLY_CODEX_BIN` must satisfy `>=0.164.0,<0.165.0`. Claude uses the package's pinned SDK dependency and does not require an external Codex executable.

Multiple instances skip occupied ports. The launch directory does not determine application storage. Temporary tasks default to the user's home directory or the first explicit `--workspace` root. Separate `--codex-home` directories isolate Codex data only, not the shared Codexly application directory.

## Start after login

Requires a stable global npm installation; temporary `npx` installations cannot register startup. Supported systems are macOS, Windows, and Ubuntu with a systemd user manager.

```bash
codexly autostart enable
codexly autostart status
```

Local and LAN startup keep the browser closed. Enable LAN startup and start immediately:

```bash
codexly autostart enable --lan --now
codexly autostart credentials
```

Use `status` for actual URLs and `credentials` to reveal the saved password explicitly.

```bash
codexly autostart logs
codexly autostart restart
codexly autostart disable
codexly autostart repair --now
```

Repeated `enable` updates the same login entry. Without `--now`, changes apply on restart or next login. Use `repair --now` after moving Node.js or the global package directory; disable startup before uninstalling. Shell profiles are not loaded, so temporary shell API keys and proxy variables are not automatically inherited. See [startup details](web-autostart.md). Desktop uses **Settings → General → Launch at login** instead.

## Updates and uninstall

Click the sidebar version when an update appears to read notes and install it, or check **Settings → About**. Manual checks query again, preferring the official registry and falling back to a mirror; mirrors may lag. Global installations can also update with:

```bash
npm install --global @bryanhu/codexly@latest
```

An older release installed into a system directory with `sudo npm install --global` may need one manual elevated upgrade. Later built-in updates request elevation when needed. Save file edits before updating and follow restart or reconnection prompts.

To uninstall:

```bash
codexly autostart disable
npm uninstall --global @bryanhu/codexly
```

Skip the first command if startup was never configured. Uninstalling preserves projects and `~/.codexly`, which may still be used by desktop.

## Troubleshooting

The server no longer continuously writes runtime logs to the terminal by default. In a computer or mobile browser, export diagnostics from **Settings → About** to download one integrated ZIP. Its `application.json` contains app and engine versions, browser information, recent browser errors, and server logs. Available native Codex diagnostics are included as `codex/diagnostics.zip` through `feedback/save` by default, without uploading feedback. App diagnostics remain available if native collection fails; `manifest.json` reports `codexDiagnostics.status` as `included` or `unavailable`. Native diagnostics do not use the app log field filters, so review the entire ZIP before sharing.

App log buffers are held in memory: restarting the server or refreshing the browser clears its respective buffer, so export soon after a problem. Server logs retain at most 2 MiB / 2,000 entries; browser errors retain at most 100 entries. Downloads are bound to the current paired session, can be claimed once, and expire after five minutes. Export again after expiration or failure. See the [diagnostic guide (中文)](../desktop/docs/diagnostics.md) for contents and analysis.

Check terminal errors, the actual URL and port, Node.js version, and network first:

```bash
codexly --version
codexly doctor
codexly start --help
```

`doctor` checks local environment and Codex readiness; it does not verify Claude API access or inference credits. For Claude-only setups, inspect Claude settings and the actual error rather than treating missing Codex configuration as an application-wide failure.
