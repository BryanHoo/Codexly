# ACP Agent

Web（含移动端）与桌面应用通过共享 ACP 运行时执行 Agent，包括 Codex、Claude、Gemini、Cursor、Copilot 等官方目录中的 Agent，以及用户自定义的 ACP 程序。应用自己的目录保存任务身份，原厂会话 ID 只用于执行与续聊。新聊天可以选择引擎，创建后引擎固定；切换新聊天的引擎不会修改已有任务。

日常操作参见[首次连接](getting-started.md)、[工作台指南](usage.md)和[Web 局域网接入](web.md)。桌面不自动提供 LAN 服务，手机使用 Web 服务所在机器的账号、工作目录与执行程序。

## 发现、安装与添加

首次启动检查运行服务的电脑上的 PATH 与常见用户 CLI 安装目录，不执行模型请求。检测到原生 ACP CLI 时复用程序及其原生配置；Codex、Claude 等需要适配器时只安装对应适配器。没有检测到的 Agent 不自动安装。已有停用记录和手动配置优先，不会被发现流程覆盖。

进入「设置 → ACP → 添加 Agent」，从官方目录选择「安装并启用」，或通过「配置自定义 Agent」指定名称、可执行程序、参数与环境变量。参数使用 JSON 字符串数组，例如 `["--acp"]`；环境变量使用 JSON 字符串对象。环境变量只在明确勾选替换后更新，已有值不会回显。安装失败保留重试入口，不发布已安装记录。

后台通知会显示已检测数量和正在准备的 Agent。在已安装的托管 Agent 上点击更新时，应用先查询官方 ACP 目录。发现更高版本时才下载安装，完成后立即显示已安装版本。若已是最新版本，应用会直接提示。下载总量可知时显示百分比，通过 npm 或 uv 下载依赖时显示当前阶段。已安装的 Agent 也可确认移除。移除不删除会话历史、本机 CLI 或共享 uv 缓存；下次检测不会自动添加已移除的 Agent，可以随时手动添加回来。

目录采用 [ACP Registry](https://github.com/agentclientprotocol/registry/blob/main/FORMAT.md) 的稳定版本快照（2026-11-14），支持 npm、uv 与当前平台二进制分发。npm 类型需要电脑已安装 Node.js/npm，Python 类型需要 uv；二进制类型不要求 Node.js。安装使用私有目录或 uv 缓存，不修改全局 Agent 安装。目录中没有的 Agent 可配置已有本机 ACP 启动命令。凭据由 Agent 自行管理，添加 Agent 不等同于完成登录。

Agent 程序、认证和原生配置均位于服务电脑。手机或其他电脑通过 Web 访问时，检测的是服务电脑。现有 Codex/Claude 任务身份不变，其他 Agent 使用独立标识，任务创建后不可改投另一个 Agent。启动命令变更在重新连接后生效；已打开的会话保留原连接。

## 连接与设置

设置页面根据 ACP 握手公布的认证方式与配置选项显示可用操作，不根据厂商名称猜测能力。供应商配置仅在 agent 声明相应接口时提供；未声明时保留原厂配置入口，不伪造连接成功。各个 Agent 独立启动和诊断，一个不可用不会阻止另一个执行。

默认配置保存在应用的 ACP 设置目录，更新只影响后续新建会话。当前会话的配置选项来自 `session/new`、`session/resume` 与配置更新响应，原会话续聊保留自身配置。仅返回 `modes` 的 v1 Agent 仍可通过共享会话设置切换模式。应用不会把普通默认值变更回写原厂配置文件。旧版应用偏好只读迁移一次，已存在的 ACP 配置优先；原厂认证和策略仍由官方 adapter 读取。

首次会话初始化先保存冻结的配置意图，再绑定原厂会话并应用默认值。配置应用或目录写入失败后，重启沿原会话恢复，不创建替代会话，也不因另一端改变全局默认值而丢失原意图。初始化完成即移除日志内的配置快照。

## 任务、历史与附件

项目、任务侧栏和已缓存历史从本地目录读取，不启动模型。原厂历史通过 ACP `session/list` 发现；打开未缓存的旧任务时，通过原 `sessionId` 加载并重放，不重新发送旧问题。发现仅使用官方接口，不解析厂商私有历史文件。

历史按有界分页加载。重放只有在位置和正文指纹均匹配时才保留已有回合、消息身份及附件，不猜测相似内容的对应关系。搜索只匹配可见正文，返回精确回合和消息锚点；冷历史搜索使用独立受限连接，支持取消并回收迟到连接。近期分页游标可继续读取，历史代际超出保留范围时明确提示刷新。

附件和导出均复核任务、项目与路径归属；宿主只传受控引用。新消息附件随应用历史保存。已有厂商历史能否还原附件内容取决于 agent 通过 ACP 返回的内容，应用不读取任意资源 URI 来补齐缺失数据。

Web 和桌面共享存储锁协议。领取与释放通过 SQLite 的 owner 比较完成；仅确认原进程不存在后回收锁。超时或未知状态明确失败，避免在无法确认写入状态时并发覆盖历史。

正文缓存与原厂会话分开：只有实际握手确认支持 `loadSession` 的会话才允许自动淘汰。同机 Web 与桌面共享 256 MiB 的正文缓存容量目标，首次使用及会话释放时按最近访问回收闲置缓存。能力未知的旧记录、仅支持 `session/resume` 或无法重放的历史保守保留。已打开、运行中及正在读取/导出的会话受跨进程租约保护，可暂时超过目标，释放后再回收。因此 256 MiB 不是整个应用目录的硬上限。

应用使用稳定 ACP v1 协议。缓存缺失后通过 ACP `session/load` 重放原厂保留的完整会话，成功响应作为回放边界；重放逐回合处理并等待写盘背压，不将全部正文一次性载入内存。重建最多保留当前及一个旧版本，过期游标明确提示刷新，不重新发送旧问题。

新生成的回答续文、工具输入和输出详情计入正文缓存预算，随正文一并回收；用户上传的文件、图片和文本附件独立保留，永久删除任务时按归属清理。正文回收不会删除原厂会话或任务管理信息。旧版混合仓储中的附件无法可靠区分来源，保守保留；这些旧附件、用户附件、不可重放历史及原厂会话目录不计入可淘汰缓存目标，仍会占用磁盘。

## 当前能力边界

支持新建任务、流式消息与工具事件、工具审批、中断、历史读取、原会话续聊、配置选项、附件、排队、搜索、临时文本生成和已确认 ACP 配置的定时任务。可用 UI 以应用已实现的 ACP 能力和 agent 返回选项为准。运行中引导仅在适配器显式公布安全引导扩展时启用；v1 没有标准后台清单及单项取消接口，因此不提供 v2 后台任务停止。

当前不公布旧执行器专属的 Goal、Review、分叉、专用压缩、技能管理与反馈上传能力。旧定时任务缺少明确的 ACP 配置时不能自动回退旧执行器，需确认配置后再执行。消息排队仍按原任务和原引擎发送；未知提交结果不会自动重发。

## 桌面分发

`pnpm build:desktop-runtime` 只构建共享 Bun 宿主及许可，不再固定打包 Codex 和 Claude。宿主作为 Tauri `externalBin` 参与签名与公证。Agent 由本机发现或用户选择后按需安装。

Windows 便携版需保留主程序、`acp-host.exe` 和 `runtime` 元数据。macOS 最低支持 14.5（Apple Silicon / Intel）。Web 服务要求 Node.js 24+；桌面只在安装 npm 类型 Agent 时需要 Node.js/npm。

## 验证入口

- `pnpm test:acp-host`：编译真实 ACP 宿主并验证传输、配置、目录与事件协议。
- `pnpm build:desktop-runtime` 后执行 `node --test tools/desktop-runtime-bundle.test.mjs`：核对目标资源、sidecar 单份布局和本机程序版本。
- `CODEXLY_REAL_RUNTIME_TEST=1 pnpm exec vitest run packages/provider-acp/src/official-agents.test.ts`：隔离环境下验证官方 adapter 握手。
- `CODEXLY_REAL_ACCOUNT_TEST=1 pnpm exec vitest run src/acp-real-history.test.ts`：使用已配置真实账号验证首发和重启续聊，会消耗模型额度。

本机验证不代替 Windows、Ubuntu、最低 macOS 版本及签名安装包的真机验收。
