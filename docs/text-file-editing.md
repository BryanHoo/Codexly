# 文本文件编辑方案

## 选择

采用 **CodeMirror 6**，由 `packages/ui` 提供共享编辑器，Web（含移动浏览器）与 Tauri 桌面复用。文件访问走现有 HTTP / Tauri 原生边界。评估日期：2026-10-10。

| 方案                            | 适配本项目的判断                                                                                   |
| ------------------------------- | -------------------------------------------------------------------------------------------------- |
| CodeMirror 6                    | 模块化、可视区域渲染、增量文本状态，支持按语言异步加载；适合现有多端、低占用目标，选用。           |
| Monaco                          | IDE 能力丰富，但官方明确不支持移动浏览器；当前需要文本编辑，额外语言服务和 Worker 管理成本不划算。 |
| textarea / contenteditable 自研 | 初始开销小，但需自行维护查找替换、撤销历史、选择和输入法兼容；长期成本高。                         |
| 富文本编辑器                    | 本次需要无损编辑代码与文档源码，不需要 Word 或富文本模型。                                         |

依据：[CodeMirror 系统指南](https://codemirror.net/docs/guide/)、[API 参考](https://codemirror.net/docs/ref/)、[官方扩展示例](https://codemirror.net/examples/)、[Monaco 官方 FAQ](https://github.com/microsoft/monaco-editor#faq)。指南明确描述了 viewport 渲染、不可变状态、按帧安排测量，以及卸载必须调用 `EditorView.destroy()`；实现遵循这些生命周期约束。

## 行为与边界

项目文件的源码预览直接作为编辑区域，不再使用编辑弹窗或额外编辑工具栏。Markdown 沿用已有的渲染 / 源码切换；源码模式直接编辑，不支持编辑的文件继续只读预览。

- 支持项目根目录及已验证 worktree 内的 UTF-8 文本，包含空文件和带 BOM 的文件。适用于代码、Markdown、JSON、YAML、XML、SQL、普通文本等。
- JS/TS/JSX/TSX、JSON、Markdown、Python、Rust、HTML、CSS、YAML、SQL、XML 提供按需语法；其余文本可以编辑，使用纯文本显示。
- 单文件最大 2 MiB，输入事务按保存后的 UTF-8 字节数校验（含 BOM、CRLF、中文及代理对）；超限粘贴或输入整笔拒绝，原正文、选择与撤销历史不变。保存和读取边界继续独立检查。正文超过 256 KiB 时在同一事务中停用解析，缩小后恢复；异步语言加载完成须重查当前大小。超限文件保留已有分页预览。
- 保留 LF / CRLF 与 UTF-8 BOM；粘贴文本匹配当前换行。为避免隐式改写，混合换行、孤立 CR、无效 UTF-8 和二进制拒绝编辑。
- Word / Office、PDF、图片等不进入文本编辑。符号链接、`.git` 路径、项目外路径不可写；现有项目外只读引用不扩大为编辑权限。
- 当前入口要求明确的项目 `rootPath`。无项目根目录的临时聊天和外部引用保持预览。首版不提供新建文件、另存为、编码转换、LSP 或自动格式化。
- 提供撤销重做和 `⌘/Ctrl+S`；正文失焦、切换窗口 / 标签页、离开文件时自动保存。输入期间不逐键写盘，没有查找替换与独立编辑工具栏。保存成功或失败通过 toast 提示，仅显示文件名；编辑受限、读取失败、超限输入或保存失败时，还须在文件面板内显示常驻原因与恢复动作，不能只依赖短暂 toast；成功文案为“xxx 文件已保存”，默认同行，宽度不足时自动换行。
- 保存链串行执行，合并重复失焦；保存期间的新输入使用回执版本继续补存，全部完成才提示成功。失败和外部冲突保留草稿，不强制覆盖磁盘。
- 面板关闭、Markdown 模式切换、页面内路由和桌面辅助窗口关闭先等待保存，失败则保持原位置。直接切换文件或卸载时补存；失败草稿仅在当前窗口内存保留，重新打开相同文件恢复；保存成功后解除草稿退出保护，会话进入有预算的闲置缓存。页面退出保护当前及保留草稿，应用退出提示包含未保存编辑；草稿不持久化，强制退出、崩溃、刷新后放弃退出提示不保证恢复。

## 数据与存储

共享契约：`ProjectTextFile { path, content, version, revision? }`，`SaveProjectTextFileRequest { path, content, expectedVersion }`，保存只返回新版本与可选修订标记，不回传全文；旧边界缺少修订标记时重开会安全回退到完整读取。

- HTTP：`GET /v1/projects/:projectId/files/text?rootPath=…&path=…`；`POST` 同一路径，查询参数携带 `rootPath`。
- 桌面：`read_project_text_file` / `save_project_text_file`；先验证项目/worktree 根目录，再进行严格路径检查。主窗口与独立文件窗口显式授权。
- 版本为原始 UTF-8 字节的 SHA-256。服务端读取完整且有界的快照；保存前校验版本，写同目录临时文件、同步磁盘、复验版本和目标，再原子替换。
- 同文件保存串行，不同文件可并行。Rust 在 `spawn_blocking` 中执行读写/哈希，Node 使用异步文件 I/O；完成后释放锁引用。
- `TEXT_FILE_CONFLICT`（HTTP 409）与 `TEXT_FILE_UNSUPPORTED`（HTTP 400）为可识别错误。认证、Host 检查、请求限制继承已有服务交付层。
- 版本比较与文件替换并不是操作系统级 CAS：不协作的外部程序在最终复验与替换之间仍存在极短竞争窗口。这里提供常规乐观并发保护，不能声称可以锁住任意外部编辑器。

## 性能约束

编辑器只在打开可编辑源码预览时下载，加载编辑器模块后先检查共享会话，再决定是否完整读取；语言解析器独立拆包。输入状态留在 CodeMirror 的持久化文本树，React 只接收布尔状态，不逐键拼接全文，不逐键发 HTTP / IPC，不后台轮询。

有项目根目录的文本文件先走共享编辑会话读取，等待期间只显示加载状态，不并行读取分页预览或渲染只读代码块。Markdown 渲染按需取用同一会话正文，切回源码复用已有文本树，不再次读取全文；可编辑正文不另存到分页 Query 缓存。不可编辑、超限或编辑器加载失败时才启用原有分页回退；没有项目根目录的外部引用继续只读分页。

保存仅提交一次完整文本。2 MiB 上限下，全文提交比补丁协议更易校验和恢复；未来若支持更大文件或高频协作，再引入增量协议。编辑文本不进入全局 Query 缓存；共享会话缓存按客户端对象隔离，用弱引用管理生命周期，键包含项目、根目录和文件路径。每个客户端最多保留 16 个闲置会话，按文本树、保存快照与累计历史估算 64 MiB 的保留预算；超额按 LRU 淘汰闲置已保存会话。活动会话、正在保存的状态和失败草稿受保护，可以超出闲置缓存预算，不能为了容量丢弃未保存修改。另设页面全局编辑/草稿容量预算：最多 16 个活动或未保存文件、32 MiB UTF-8 正文预留，每个文件在读取前预留完整 2 MiB，所有客户端/项目共用，重复打开及在途读取只占一份；满额的新文件回退分页只读并提示先处理已有草稿。失败读取或闲置且已保存时归还预留，已有草稿重开不受满额影响。闲置未保存会话释放撤销历史、视图绑定与解析状态，复用正文文本树并保留选择、滚动、换行与保存版本。正文预留与缓存估算不是 JS 堆上限，`history({ minDepth: 30 })` 也不是字节级内存限制。保存后只失效对应文件预览与所属根目录 Git 状态。

预览内编辑构建测量：编辑器主异步资源约 301.5 kB 原始 / 98.1 kB gzip；这不包含按需语言包和所有共享依赖。Web 初始静态闭包约 293 KiB gzip，仍满足 320 KiB 预算。桌面工作区/Markdown 场景预算分别调整为 1,560,000 / 2,040,000 字节，新增完整编辑场景 2,050,000 字节预算；首屏和单异步资源上限保持原值。

状态层实测：本机 Node 24 上，2,097,137 字节文档执行 1,000 次同长度局部替换约 29.6 ms，GC 后保留堆增长约 8.24 MiB。该数据包含状态构造与修改，不包含 DOM、WebView 和网络，不能代替真实输入延迟测量。

### 分屏会话复用

- 右栏仍只挂载活动分屏，卸载时销毁 `EditorView`，保留会话的持久化文本树、选择和滚动快照；已保存会话继续保留撤销历史和语言状态，闲置未保存草稿则执行容量压缩。重新挂载只重配视图回调，不将全文序列化为字符串再建树；卸载清除视图闭包，避免缓存持有已销毁 DOM。
- 同一文件的首次加载及重新校验均合并在途请求。短暂失焦不取消共享读取，切回来等待同一结果；预算淘汰时中止可取消请求。桌面客户端在 IPC 启动前（含等待运行时期间）检查 AbortSignal；已经进入操作系统的同步读取不能强制取消，结果由共享缓存复用。
- 每次重新激活已保存会话，HTTP `GET /v1/projects/:projectId/files/text/revision?rootPath=…&path=…` 或原生命令 `read_project_text_file_revision` 只检查元数据并返回 `{ revision }`；修订标记变化才重新读取全文。未保存草稿与正在保存的会话直接复用，后续保存仍进行 SHA-256 冲突校验。
- 修订标记绑定完整读取的快照及原子保存回执。Node 使用设备号、inode、大小、纳秒 mtime/ctime 与创建时间；Rust 使用大小、修改/创建时间，以及 Unix 的设备号、inode 和纳秒 ctime，Windows 增加原生文件属性与时间字段。元数据检查是缓存失效机制，不替代正文 SHA-256：文件系统时间精度、Windows 上刻意恢复同长度文件时间等情况可能使标记保持相同，保存仍会拒绝实际正文冲突。校验失败或文件删除时不展示旧的已保存编辑状态。
- 使用 Chrome DevTools MCP 经 CDP 连接运行中的 Chrome，在真实共享组件、活动分屏卸载规则的内存服务验证页中，四屏切换 12 次，全文读取从修复前 13 次降至 4 次（每份文件首次各 1 次），另有 9 次元数据检查；连续重挂 3 次仍为 4 次全文读取。该页面验证共享挂载流程，磁盘与 IPC 边界分别由 Node/Rust/客户端测试覆盖。
- 自动回归覆盖条目/字节预算、活动和失败草稿保护、在途读取合并、外部版本变化、元数据变化但正文相同、校验失败重试，以及文本树、CRLF、选择和撤销历史保留。

本轮验证：Web 全量 2,113 项通过（20 项跳过），桌面前端 489 项通过；Rust 全量 713 项通过（10 项忽略）及集成测试通过，最后的回执变更另做文本文件专项验证。两端类型检查、Lint、Rust Clippy、Web/桌面/legacy 构建及资源预算通过。Chrome 中保存后切屏保留同一文本树和选区、撤销成功；外部变更新增 1 次全文读取，1,000 行文件的滚动位置在重挂前后均为 1,200 px。原生 WebView 与 Windows/Ubuntu 真机未在本轮验收。

### 编辑受限提示与恢复

- 容量满、编辑器加载失败与不支持编辑的文件须说明只读原因，以及仍可查看/复制正文；容量满与临时加载失败提供“重试编辑”，无需关闭或重新打开文件。重试期间保留只读正文与说明，按钮显示进度并禁用重复提交；成功后原位恢复编辑。
- 超限输入说明是编辑后的文件会超过 2 MiB，整笔输入未应用、原内容未变、仍可继续编辑；提供减少粘贴量/删除部分正文的建议。提示可主动确认，并在下一次有效正文修改后解除。
- 保存失败或冲突随会话保留原因，提供“重试保存”；成功才清除保存失败提示。超限提示解除后仍须显示此前的保存失败，不能覆盖未解决的错误。冲突重试仍遵循 expectedVersion，禁止强制覆盖。
- 大正文解析降级说明高亮暂停、仍可编辑和保存，缩小后自动恢复；只在阈值变化时更新提示，不逐键复制正文或重渲染 React。
- 两端复用 `core/text-editor-notice` 与同一份中英文文案。Chrome CDP 验证实际容量满的常驻原因、恢复编辑、保存失败与按钮重试、超限后继续输入、读取失败原位恢复，以及 390 × 844 布局无横向溢出。组件测试覆盖各原因、动作及可访问提示，保存状态测试覆盖提示保留与解除。

提示功能验证：Web 全量 2,142 项通过（20 项跳过），桌面 489 项测试及 `check:web` 通过；两端类型、Lint、架构、常规/legacy 构建与资源预算通过。共享专项 39 项通过，Chrome CDP 验证常驻提示、原位恢复、按钮保存重试及移动布局。
