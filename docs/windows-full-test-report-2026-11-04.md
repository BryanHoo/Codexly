## 修复

1. **首张 Mermaid 图表功能断言过早超时。** 首次懒加载和初始化在本机约需 1.3–1.5 秒，超过 `expect.poll` 默认的一秒窗口；失败截图中图表已正确渲染。只为首次图表功能断言设置十秒等待窗口，保留中文 SVG 内容及流式图表保留断言。修复前定向测试失败，修复后 Chromium/WebKit 对 Web、桌面两端的八项测试通过。
2. **文档标签懒加载就绪等待不足。** WebKit 首次打开文档时，标签栏及 Activity/Portal 尚未完成提交，导致滚动夹具和外置底栏断言过早失败。与同文件既有懒加载检查一致，首次就绪等待使用五秒窗口；标签布局、滚动不重渲染、底栏可见性和草稿保留等原断言全部保留。修复前两项失败，修复后十四项定向测试通过。
3. **共享发送按钮内部触控高度不足。** 外框高 24 px，扣除上下边框后按钮只剩 22 px，三浏览器均违反既有最小高度检查。将共享外框改为 26 px，使内部按钮至少 24 px；Web 和桌面共用同一处修改。E2E 补充下拉按钮高度检查，修复后三浏览器六项移动布局测试通过，相关共享组件十八项、单元测试三十七项通过，Web 体积预算保持通过。
4. **归档搜索输入与 Select 焦点恢复竞争。** WebKit trace 显示 `fill` 完成后搜索框仍为空，连续十次中三次失败。测试等待选择器关闭后的焦点恢复，再输入并校验文本；日期时钟也限定在工作台就绪之后设置。修复后连续十次通过，没有重试输入、强制点击或固定等待。
5. **设置页初始焦点与失焦测试时序。** 先等待设置页初始焦点完成，再输入并校验搜索词；保存测试用点击标题离开编辑器，验证真实用户失焦流程。初轮有一次搜索框为空，连续复现还发现两次通知消失断言失败；保留原始 trace，修复后连续十次通过。
6. **Trace 夹具的恢复快照与完成事件矛盾。** 启用完整 trace 的全量运行暴露四项失败：网络记录显示回合完成后恢复请求拿到 checkpoint 14，却仍是 `running` 回合，导致停止按钮重新出现。夹具现在先同步完成状态，再发布完成事件，使恢复快照与事件一致。保留原停止按钮、动画、折叠、滚动和主题断言，三浏览器完整十二项用例各重复两轮，共二十四项通过。

生产修改仅为共享按钮高度，不改变调度、懒加载或性能预算。桌面浏览器套件同时覆盖共享 UI 和 Web 组件，双端共用实现未复制。

## 性能与原始现场

- Web 首屏压缩传输 **354.37 KiB / 360 KiB**；工作台就绪 **517.44 KiB / 520 KiB**、40 个请求；最大异步资源 **464.06 KiB / 640 KiB**，满足仓库预算。
- 浏览器诊断中，100 回合后追加到绘制约 **81.1 ms**。这是诊断数据，不是额外硬门槛，不代表所有资源指标都满足优化目标。
- WebView2 启动放行至可交互 **486.1 ms**；Runtime 增量提交/渲染 P95 **19.1 ms**，不是完整进程冷启动或显示器呈现时间。
- 200 次可信系统按键到 xterm `onRender` P95 **34.1 ms**；输入到输出 **1.8 ms**，输出到渲染 **32.7 ms**。既有 **30 ms 观察目标仍未达成**，没有放宽目标；现有功能及性能硬门禁通过。
- 12 个终端三轮空闲时，主进程 CPU **0%–0.08%**、工作集约 **35.5–35.7 MiB**，进程树 CPU **0.42%–0.65%**，终端 IPC 增量 **0**。12 终端同时输出时主进程 CPU **35.05%**、进程树 **178.60%**；清理约 **73.2 ms**，剩余原生会话和输入/未确认输出队列均为 **0**。
- CPU 100% 代表一个逻辑核；进程树包含 PowerShell、ConPTY、WebView2/GPU，工作集含共享页，不能视为独占物理内存。数据保留本机其他程序背景负载。
- 首轮桌面浏览器保留三项失败；Web E2E 首轮 467 项通过、4 项失败、3 项同组未运行，次轮 470 项通过、2 项失败、2 项同组未运行。Chromium 空白启动单独连续十次通过，原始现场保留，没有据此扩大生产超时或加入自动重试。
- Rust 默认忽略的真实 Codex 生命周期测试遵循 Windows CI 边界，通过真实原生 WebView 链路验证；macOS/Linux 专属峰值 RSS 测试不适用于 Windows。供应链检查保留既有允许的重复依赖与 `clipboard-win 5.4.1` 撤回版本提示。
